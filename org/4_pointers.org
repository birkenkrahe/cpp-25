* Getting the Address of a Variable

- The address-of operator ~&~ returns the memory address of a variable.

- Where exactly is this "memory address" on the computer?
  #+begin_quote
  It's in RAM (Random Access Memory) of the computer, usually
  somewhere in the "stack" or in the "heap".
  #+end_quote

- When the variable is undefined, you get any old value:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    double amount; // double precision floating-point variable

    cout << "Address: " <<  &amount // address-of variable
    << ", value = " << amount  // value of variable
    << ", Size = " <<  sizeof(amount) << " bytes." << endl; // size of variable
  #+end_src

  #+RESULTS:
  : Address: 0x7ffe2c1314b0, value = 0, Size = 8 bytes.

- Why are the addresses always different?
  #+begin_quote
  Because of ASLR (Address Space Layout Randomization) - done for
  security reasons (harder to inject malicious code in changing
  memory).
  #+end_quote

- The following fragment declares three variables.
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results none
    char letter;  // 1 byte   ( 8 bits)
    short number; // 2 bytes  (16 bits)
    float amount; // 4 bytes  (32 bits)
  #+end_src

- In the computer memory, they may be arranged like this:

  #+caption: Variables and their addresses (Gaddis fig 9-1).
  [[../img/addresses.png]]

- The address itself is represented in hexadecimal (base 16)
  format. On a 64-bit computer system, the length of an address is
  typically 64 bits or 8 bytes.

- How many addresses can be represented on a 64-bit computer system?
  #+begin_quote
  2^64 with 0 or 1 on 64 positions (ca. 18 quintillion) -
  #+end_quote

  If so, how would we know this?
  #+begin_quote
  Yes, each byte in the memory has a unique physical address.
  #+end_quote

* Pointer Variables

- A pointer variable is a variable that holds a memory address. When
  it is used to point at data, its type has to coincide with the type
  of the data: An integer pointer can point at an integer, etc.

- When an array is passed to a function, it "decays" to a pointer to
  the first array element.

- What happens in the following code example with regard to variable
  addresses?
  #+name: pointer values
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    using namespace std;

    void showValues(int [], int);  // function prototype

    int main()
    {
      const int SIZE = 5;
      int numbers[SIZE] = {1,2,3,4,5}; // initialize array of SIZE elementsx
      showValues(numbers,SIZE); // call function
      return 0;
    }

    void showValues(int values[], int size)
    {
      for (int count = 0; count < size; count++)
        cout << values[count] << " ";
    }
  #+end_src

  #+RESULTS: pointer values
  : 1 2 3 4 5

- Explanatinaon:
  #+begin_quote
  1. In ~main~, the name of the array numbers and its =SIZE= are passed to
     the function showValues
  2. In the function, the =values= parameter receives the address of the
     array =numbers= - it points to =numbers[0]=
  3. Inside showValues, anything done to =values= is done to =numbers=.
  #+end_quote

* Pointers vs. references and reason for pointers

- Pointer variables are similar to reference variables but they
  require more work from you.

- To make a pointer variable reference another item in memory, you
  have to write code to *fetch* the memory address of that item and
  *assign* it to the pointer variable (using the address-of operator
  ~&~).

- When you use a pointer to *store* a value in the memory location that
  the pointer references, you have to specify that it should be stored
  at a location rather than in the pointer variable itself (using the
  indirection or dereference operator ~*~).

- Programmers use reference variables to make changes permanent
  between calling routines and functions. But why use pointers?
  #+begin_quote
  1. Pointers are necessary when you want to allocate memory
     dynamically.
  2. Pointer are useful in algorithms that need to manipulate arrays
     fast and especially text (stored in strings).
  3. In object-oriented programming (OOP), pointers are useful to
     create and work with objects and for sharing access.
  #+end_quote

- Example: Walking through a string using a pointer
  #+begin_src cpp :main no :includes :results output :exports both
    #include <iostream>

    int main() {
      const char* greeting = "Hello, world"; // Declare a C-style string as constant (literal) character pointer.
      std::cout << greeting << std::endl; // Print the whole string.

      // The pointer points at greeting[0].
      std::cout << *greeting << std::endl;// 'H'
      // Moving forward, the pointer points at greeting[1]
      std::cout << *(greeting + 1) << std::endl; // 'e'

      // Traverse the C-style string with a pointer
      const char* p = greeting;
      while( *p != '\0') // check if the char pointed at is \0
        {
          std::cout << *p;
          ++p;  // move pointer to next memory cell (byte)
        }

      return 0;
    }
  #+end_src

  #+RESULTS:
  : Hello, world
  : H
  : e
  : Hello, worldello, worldllo, worldlo, worldo, world, world worldworldorldrldldd

* Creating and using pointer variables

- What does =int* ptr;= mean?
  #+begin_quote
  1. =ptr= is a pointer variable that points to an =int= variable.
  2. =ptr= can hold the value of a memory address (of 4 bytes).
  3. =ptr= at the moment is unassigned (it can point anywhere).
  #+end_quote

- What's the difference between =int* ptr= and =int *ptr= ?
  #+begin_quote
  There is none.
  #+end_quote

- *Rule:* Always initialize a pointer variable with the ~nullptr~ -
  otherwise you're changing a memory address somewhere.
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both
    int* foo = nullptr; // C++11
    int* bar = NULL;    // C or in older C++

    printf("%p %p\n", foo, bar);
    cout << foo << " " << bar;
  #+end_src

  #+RESULTS:
  : (nil) (nil)
  : 0 0

* Indirect access to variables

- Pointers allow you to indirectly access and modify the variable
  being pointed to using the *indirection* operator ~*~ (asterisk).

- Example program:
  1) Assign the address of a variable to a pointer.
  2) Print the value of the variable using the dereferenced pointer.
  3) Assign a value to the location pointed to by the pointer.
  4) Print the value of the variable using the dereferenced pointer.

  #+name: indirection operator
  #+begin_src C++ :main no :includes :results output :exports both
    // This program demonstrates the use of the indirection operator.
    #include <iostream>
    using namespace std;

    int main()
    {
      int x = 42; // Integer variable
      int *ptr = nullptr; // Pointer variable that can point to an int
      ptr = &x; // Store the address of x in the pointer

      // Use x and ptr to display the VALUE in x
      cout << "Value of x (direct):               " <<  x    << endl
           << "Value of x (indirect via pointer): " <<  *ptr << endl;

      // Assign 99 to the location pointed to by ptr.
      // This will assign 99 to x.
      (*ptr) = 99;

      // Use x and ptr to display the VALUE in x
      cout << "Value of x (direct):               " << x    << endl
           << "Value of x (indirect via pointer): " << *ptr << endl;

      return 0;
    }
  #+end_src

  #+RESULTS: indirection operator
  : Value of x (direct):               42
  : Value of x (indirect via pointer): 42
  : Value of x (direct):               99
  : Value of x (indirect via pointer): 99

- Explanation:
  #+begin_example
  [ptr] ---> addr [x: 42]  // ptr is assigned &x

  [ptr] ---*---> 42   // *ptr holds 42

  [ptr] ---*---> 99   // *ptr is assigned 99

  [ptr] ---> addr [x: 99]  // x holds 99
#+end_example

* Re-pointing pointers

- Since pointers hold memory addresses, they can be re-pointed to
  other addresses. That happens when you initialize a pointer with the
  ~nullptr~ and then assign the address =&x= of an existing variable =x=.

- The following code uses one pointer =ptr= to change the values in
  three different variables:

  #+name: Repointing pointers
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both
    // Define two integer variables and one integer pointer.
    int x = 25, y = 50;
    int *ptr = nullptr;

    // Display the contents of the integer variables.
    cout << "x = "   << x << ", y = " << y << endl;

    // Use the pointer to manipulate the variables.
    ptr = &x; // Store address of x in pointer

    (*ptr) += 100; // Add 100 to the value in x

    ptr = &y; // Store address of y in pointer

    (*ptr) += 100; // Add 100 to the value in y

    // Display the contents of the integer variables.
    cout << "x = " << x << ", y = " << y << endl;
  #+end_src

  #+RESULTS: Repointing pointers
  : x = 25, y = 50
  : x = 125, y = 150

* Arrays and pointers

- What is the relationship between arrays and pointers?
  #+begin_quote
  Array names can be used as a constant pointer (that means
  that you cannot change it to point elsehwere), and pointer
  can be used as array names.
  #+end_quote

- Example: What will this program print?
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes

- How can one retrieve the entire array =numbers= using a pointer?
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    short numbers[] = {10, 20, 30, 40, 50};
    cout << *numbers  << " "    // retrieving numbers[0]
    << *(numbers + 1) << " "    // retrieving numbers[1]...
    << *(numbers + 2) << " "
    << *(numbers + 3) << " "
    << *(numbers + 4) << endl;
  #+end_src

- Do you think this would also work as a loop?

    short numbers[] = {10, 20, 30, 40, 50};
    for (int i=0; i<5; i++)
      cout << *(numbers + i) << " ";   // same as num[i]

  a constant pointer (to the array's first element):
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes

- Can you understand how this ~for~ loop works?
  #+begin_quote
  1. The *start* point(er) is =number[0]= same as =number= and accessed
     as a dereferenced pointer =*p=.
  2. The *stop* pointer(er) checks if the address of =p= is smaller than
     the address of =number= (=number[0]= offset by five ~short~ numbers).
  3. The *incrementor* moves the pointer by one address of 2 bytes each.
  #+end_quote

* Why you can step through arrays using pointers
#+attr_html: :width 600px :float nil:
#+caption: Array elements are stored in contiguous memory locations (Gaddis Fig. 9-5)
[[../img/memory_storage.png]]

When you add a value to a pointer, you are adding that value times
the size of the data type being referenced by the pointer -
=*(number + 1)= moves 2 bytes forward when =number= is a ~short~ variable,
and 4 bytes when it is an ~int~ variable: So =*(number +1)= is actually
=*(number + 1 * sizeof(short))= etc.

* PRACTICE Using subscripts with pointers

- This program reveals the deep relationship between arrays and
  pointers once more. We can come up with four different ways of
  printing the array elements using pointers.

- In the following program, subscript notation is used with a pointer
  variable, and pointer notation is used with an array name.
  1. An array of ~double~ =coins= is created.
  2. A pointer-to-double =doublePtr= is created.
  3. =coins= is assigned to =doublePtr= (no ~&~ operator needed!)
  4. The =coins= array is printed using the subscripted =doublePtr=.
  5. The =coins= array is printed using pointer notation.
  6. The =coins= array is printed using pointer arithmetic.
  7. The =coins= array is printed using referencing and dereferencing.

- Starter code:

  #+begin_src C++ :main no :includes :results output :exports both
    // Demonstrate connection between arrays and pointers
    // Create an array of double variables, and a pointer-to-double
    // Display the array elements using pointers in four ways.
    // Sample output: 0.05 0.1 0.25 0.5 1
    #include <iostream>
    using namespace std;

    int main()
    {
      // Declare array size, array, and pointer
      const int NUM_COINS = 5;
      double coins[NUM_COINS] {0.05, 0.1, 0.25, 0.5, 1.0};
      double *doublePtr = nullptr;

      // Point the pointer at the array.
      doublePtr = coins;

      // Display array using a pointer subscription.
      for (int count=0; count < NUM_COINS; count++)
        cout << doublePtr[count] << " ";

      cout << endl;
      // Display array using pointer notation.
      for (int count=0; count < NUM_COINS; count++)
        cout << *(coins + count) << " ";

      cout << endl;
      // Display array using pointer arithmetic (using addresses)
      for (double *p=coins; p < coins + NUM_COINS; p++)
        cout << *p << " ";

      cout << endl;
      // Display array with referenced array and dereferenced pointers
      for (int count=0; count < NUM_COINS; count++)
        {
          doublePtr = &coins[count]; // store address of element in pointer
          cout << *doublePtr << " "; // dereference the pointer
        }
      return 0;
    }
  #+end_src

* Dynamic memory allocation

- Variables may be created and destroyed while a program is running.

- If you know how many variables you need during execution, you can
  define them up front.
  1) To calculate the area of a rectangle: =length=, =width=, =area=.
  2) To compute payroll for 30 employees: an array =payRoll[30]=.

- When you don't know that, you need to allocate memory on the fly,
  during program execution:
  1) To store a list of names from a file if you don't know the number
     of names in the list.
  2) To run an image processing application where you need to store
     pixel data based on the resolution of images loaded at runtime.

- Most realtime data problems are of the second sort. They require
  *dynamic memory allocation*, and you need pointers for that.
