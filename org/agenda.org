1) What is an abstraction? Can you give an example (life, math or
   code)? What's the price to be paid for "abstracting"?
   #+begin_quote
   - *Life*: Calling Jim, Joe, John and Jane "students" is an abstraction in
     real life. It suppresses the details of their persons in order to
     be to address them with one term.
    
   - *Math*: An integer is a mathematical abstraction. It captures the idea of
     whole numbers ignoring their individual differences.

   - *Code:* The ~int~ data type is a computing abstraction of an integer
     number.

   - *Price*: Abstractions remove detail thereby removing whatever
     they're used for further from the real world of complexity.
   #+end_quote

7) What's the meaning of ~{ }~?
   #+begin_quote
   The curly braces group a *block* of statements together. The compiler
   treats these as one unit. They also define a *scope*, a region where
   a variable exists and can be used.
   
   - After a function declaration, ={}= mark the block of code belonging
     to that function: =main() {}= or =void hello(string & name) {};=
   - After ~if~, or ~else if~, the statements in ={}= form the block of code
     that runs only if the condition is ~true~, after ~else~ only if the
     condition is ~false~. Also: ~switch~.
   - After ~for~, ~while~ or ~do~ (~while~), the statements in ={}= are repeated
     as long as the loop condition is ~true~.
   #+end_quote

8) What's the meaning of =return 0= - do you have to use it?
   #+begin_quote
   You don't have to (compiler-dependent) but you should use it:
   - =return 0;= uses the =return= statement to terminate the current
     function (~main~ in this case) and return the value =0= to indicate
     that the program ran successfully.
   - =return EXIT_SUCCESS;= is the same thing using a constant from
     ~<cstdlib>~ (which you must ~#include~.

   Post-mortem:
   
   - There are many more ~return~ codes on Unix/POSIX-compliant systems that
     the system can use. 
     |  Code | Meaning                                   |
     |-------+-------------------------------------------|
     |     0 | Success                                   |
     |     1 | General error (~EXIT_FAILURE~)              |
     |     2 | Misuse of shell builtins (Bash)           |
     |   126 | Command invoked cannot execute            |
     |   127 | Command not found                         |
     |   128 | Invalid exit argument                     |
     | 128+n | Fatal error signal "n" (e.g., 130 = ^C)   |
     |   255 | Exit status out of range / implementation |

   - In networking, there are many more integer constants/flags used
     in sockets to identify errors, options and connection states
     (these are not ~return~ codes as such though). A few examples:
     | Code | Name          | Meaning                         |
     |------+---------------+---------------------------------|
     |   98 | EADDRINUSE    | Address already in use          |
     |   99 | EADDRNOTAVAIL | Cannot assign requested address |
     |  111 | ECONNREFUSED  | Connection refused              |
     |  113 | EHOSTUNREACH  | No route to host                |
     |  104 | ECONNRESET    | Connection reset by peer        |
     |  110 | ETIMEDOUT     | Connection timed out            |
     |  107 | ENOTCONN      | Socket is not connected         |
     |  106 | EISCONN       | Socket is already connected     |
     |   32 | EPIPE         | Broken pipe (write on closed)   |
     |  101 | ENETUNREACH   | Network is unreachable          |

   #+end_quote

9) What's the meaning of =std::cout=? Do you have to use it?
   #+begin_quote
   - The statement =std::cout= consists of:
     1) ~std~ for the standard C++ ~namespace~ (think of it as a library of
        useful functions).
     2) ~::~ the *scope resolution operator* which tells the compiler where
        to look for names (like ~cout~).
     3) ~cout~ is the *character output stream object* for console (stdout)
        output.
   - So the 1st answer is: =std::cout= is the standard output stream
     object from the std namespace.
   - Do you have to use it? No, you can use this instead: =using
     namespace std; cout << "Hello";= - It's in the OneCompiler.com/cpp
     template.
   #+end_quote

10) Do I have to use the output stream object ~cout~ to print in C++?
    #+begin_quote
    No, the trusty old C function ~printf~ works just as well and gives
    you a lot more flexibility, too. Recall that it requires format
    specifiers like ~%d~ and ~%s~ and arguments to work, and that it is a C
    function.
    #+end_quote

    #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
      char name[19]="Marcus Birkenkrahe";
      printf("%s\n", name);

      int i=100; float f=3.14;
      printf("%d %.2f \n", i, f);
    #+end_src

    #+RESULTS:
    : Marcus Birkenkrahe
    : 100 3.14

** Review (Tuesday)

1. What does the keyword ~auto~ do?
   #+begin_quote
  The keyword ~auto~ tells the compiler to deduce the type of a declared
  variable from its initializer (the value initially stored in it).
   #+end_quote
   #+begin_src C++ :main yes :includes <iostream> :namespaces std :results output :exports both
     auto foo = 42;       // deduced as int
     auto bar = 3.14;     // deduced as double
     auto baz = "Bob"; // deduced as const char*

     printf("foo = %d\nbar = %g\nbaz = %s\n", 
            foo, bar, baz);
   #+end_src

   #+RESULTS:
   : foo = 42
   : bar = 3.14
   : baz = Bob

2. What's an "exception"?
   #+begin_quote
   An exception is a run-time error that can be thrown and caught to
   handle errors without crashing the program.
   #+end_quote
   #+begin_src C++ :main no :includes
     #include <iostream>
     using namespace std;

     int main()
     {
       try { 
         int x = 10;
         if (x == 0) // throw an exception for div by zero
           throw "Division by zero not allowed!";
         cout << 10 / x << endl; // x is not 0
       }
       catch (const char *msg)
         { // catch the exception if x is 0
           cout << "Exception caught: " << msg << endl;
         }
       return 0;
     }
   #+end_src

3. How should you approach writing functions?
   #+begin_quote
   1. Write and test the function body without the function.
   2. Identify the ~return~ type (if none: ~void~)
   3. Identify the argument list (if empty: ~void~)
   4. Create a prototype, e.g. =void hello(void);= (no body)
   5. Create a definition with body between ~{ }~
   #+end_quote

4. What are ~stdin~, ~stdout~ and ~stderr~?
   #+begin_quote
    ~stdin~, ~stdout~ and ~stderr~ are data streams for input, output and
    error data. They are connected to devices like keyboard, screen
    file, network socket, etc. They can be redirected anywhere.
   #+end_quote

5. What does it mean that C-style arrays are "static"?
   #+begin_quote
   C-style arrays are called "static" because the size of the array
   must be known at compile-time (e.g. =int a[10];=), and the memory for
   all array elements is allocated in one block (that cannot be
   changed at run-time).
   #+end_quote
