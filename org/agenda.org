7) What's the meaning of ~{ }~?
   #+begin_quote
   The curly braces group a *block* of statements together. The compiler
   treats these as one unit. They also define a *scope*, a region where
   a variable exists and can be used.
   
   - After a function declaration, ={}= mark the block of code belonging
     to that function: =main() {}= or =void hello(string & name) {};=
   - After ~if~, or ~else if~, the statements in ={}= form the block of code
     that runs only if the condition is ~true~, after ~else~ only if the
     condition is ~false~. Also: ~switch~.
   - After ~for~, ~while~ or ~do~ (~while~), the statements in ={}= are repeated
     as long as the loop condition is ~true~.
   #+end_quote

8) What's the meaning of =return 0= - do you have to use it?
   #+begin_quote
   You don't have to (compiler-dependent) but you should use it:
   - =return 0;= uses the =return= statement to terminate the current
     function (~main~ in this case) and return the value =0= to indicate
     that the program ran successfully.
   - =return EXIT_SUCCESS;= is the same thing using a constant from
     ~<cstdlib>~ (which you must ~#include~.

   Post-mortem:
   
   - There are many more ~return~ codes on Unix/POSIX-compliant systems that
     the system can use. 
     |  Code | Meaning                                   |
     |-------+-------------------------------------------|
     |     0 | Success                                   |
     |     1 | General error (~EXIT_FAILURE~)              |
     |     2 | Misuse of shell builtins (Bash)           |
     |   126 | Command invoked cannot execute            |
     |   127 | Command not found                         |
     |   128 | Invalid exit argument                     |
     | 128+n | Fatal error signal "n" (e.g., 130 = ^C)   |
     |   255 | Exit status out of range / implementation |

   - In networking, there are many more integer constants/flags used
     in sockets to identify errors, options and connection states
     (these are not ~return~ codes as such though). A few examples:
     | Code | Name          | Meaning                         |

     |   99 | EADDRNOTAVAIL | Cannot assign requested address |

     |  104 | ECONNRESET    | Connection reset by peer        |

9) What's the meaning of =std::cout=? Do you have to use it?
   #+begin_quote
   - The statement =std::cout= consists of:
     1) ~std~ for the standard C++ ~namespace~ (think of it as a library of
        useful functions).
     2) ~::~ the *scope resolution operator* which tells the compiler where
        to look for names (like ~cout~).
     3) ~cout~ is the *character output stream object* for console (stdout)
        output.
   - So the 1st answer is: =std::cout= is the standard output stream
     object from the std namespace.
   - Do you have to use it? No, you can use this instead: =using
     namespace std; cout << "Hello";= - It's in the OneCompiler.com/cpp
     template.
   #+end_quote

** Review

1. What does the keyword ~auto~ do?
   #+begin_quote
  The keyword ~auto~ tells the compiler to deduce the type of a declared
  variable from its initializer (the value initially stored in it).

  Not recommended at the start - highly recommended for production
  code: because it is safer and shorter.
   #+end_quote
   #+begin_src C++ :main yes :includes <iostream> :namespaces std :results output :exports both
     auto foo = 42;       // deduced as int
     auto bar = 3.14;     // deduced as double
     auto baz = "Bob"; // deduced as const char*

     printf("foo = %d\nbar = %g\nbaz = %s\n", 
            foo, bar, baz);
   #+end_src

   #+RESULTS:
   : foo = 42
   : bar = 3.14
   : baz = Bob

2. What's an "exception"?
   #+begin_quote
   An exception is a run-time error that can be "thrown" and "caught"
   to handle errors without crashing the program.
   #+end_quote
   #+begin_src C++ :main no :includes
     #include <iostream>
     using namespace std;

     int main()
     {
       try { 
         int x = 0;
         if (x == 0) // throw an exception for div by zero
           throw "Division by zero not allowed!";
         cout << 10 / x << endl; // x is not 0
       }
       catch (const char *msg)
         { // catch the exception if x is 0
           cout << "Exception caught: " << msg << endl;
         }
       return 0;
     }
   #+end_src

   #+RESULTS:
   : Exception caught: Division by zero not allowed!

3. How should you approach writing functions?
   #+begin_quote
   1. Write and test the function body without the function.
   2. Identify the ~return~ type (if none: ~void~)
   3. Identify the argument list (if empty: ~void~)
   4. Create a prototype, e.g. =void hello(void);= (no body)
   5. Create a definition with body between ~{ }~
   #+end_quote

4. What are ~stdin~, ~stdout~ and ~stderr~?
   #+begin_quote
    ~stdin~, ~stdout~ and ~stderr~ are data streams for input, output and
    error data. They are connected to devices like keyboard, screen
    file, network socket, etc. They can be redirected anywhere.
   #+end_quote

5. What does it mean that C-style arrays are "static"?
   #+begin_quote
   C-style arrays are called "static" because the size of the array
   must be known at compile-time (e.g. =int a[10];=), and the memory for
   all array elements is allocated in one block (that cannot be
   changed at run-time).
   #+end_quote

6. What's the difference between compile-time and run-time? What about
   errors?
   #+begin_quote
   - Compile-time is when the compiler translates source code (C++)
     into machine code. Errors are: syntax errors, missing semicolons,
     undeclared variables, type mismatches.
   - Run-time is when the program is actually executed. Errors are:
     division by zero, invalid memory access, file not found.
   #+end_quote

** Post-mortem: Reverse range-base ~for~ loops

Range-based ~for~ loops can be reversed but it's complicated: The
container needs to have a ~begin()~ and ~end()~ iterator. ~std::string~ in
the example below does. And you need the C++20 standard, so you need
to compile with =g++ -std=c++20=:

#+begin_src C++ :tangle ../src/rev.cpp :main no :includes :results output :flags -std=c++20
  #include <iostream>
  #include <ranges>

  int main()
  {
    std::string str;
    std::cin >> str;

    for (char c : str | std::views::reverse)
      std::cout << c;
      
    return 0;
  }
#+end_src

** Post-mortem: Pointers as loop variables in range-based loops

In a range-based for loop, the loop variable is bound to each element
of the range. If you declare it as a pointer, you'll just be iterating
over the values, and they have to be pointers already. Here is an
example:

#+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
  int a=10,b=20,c=30;
  int arr[] {a,b,c};
  // loop variable is an integer
    for (int x : arr) 
      cout << x << " ";
  // loop variable is a reference
  cout << endl;
  for (int &x : arr)
    {
      x++; // modifies array elements
      cout << x << " ";
    }
  cout << endl;  
  // loop variable is a pointer only works for pointer arrays
  int * arr2[] {&a,&b,&c}; // array of addresses
  for (int *p : arr2) // arr decays to int*
     cout << *p << " ";
#+end_src

#+RESULTS:
: 10 20 30 
: 11 21 31 
: 10 20 30

** Bonus: Where do C++ rules come from?

For example: "When passing a C-style array to a C++ function, the
array decays to a pointer to its first element." Where is that
written?

When you pass an array to a function in C++, the array does not get
copied as a whole. Instead, the language requires array-to-pointer
conversion. The *standard* says:

- [[https://eel.is/c++draft/conv.array][conv.array]] (C++23 §7.3.3.4): *An lvalue or rvalue of type “array of
  T” can be converted to a prvalue of type “pointer to T”. The result
  is a pointer to the first element of the array.*
- [[https://eel.is/c++draft/dcl.fct][dcl.fct]] (C++23 §9.3.5.6): A parameter declared as “array of T” is
  adjusted to be “pointer to T”.

There is no built-in notion of a pointer to an entire array in
function calls; the array decays to the address of its first
element. If you want to treat the whole collection as a copyable
object, you must use types like =std::array= or =std::vector=.

The machine-level *heuristic* ("the computer can only point at one
address at a time") helps explain why the language designers chose
this rule.

*Sources:* The links point to unofficial mirrors of the ISO C++ standard
text: for example, [[https://eel.is/c++draft/][eel.is/c++draft ]] is maintained by Richard Smith (a
C++ committee member). It’s a continuously updated draft that matches
the official ISO C++ standard (like C++20, C++23), but is freely
browsable online. The official standard is published by ISO
(e.g. ISO/IEC 14882:2023 – Programming Language C++), but ISO sells it
as a paid PDF. That’s why most people use the draft mirrors (eel.is,
or sometimes cppreference’s summaries).

   #+end_quote

   #+end_quote
