* Two types of initialization

1) Traditional C-style copy syntax: =value[2]={100,200};=

2) C++ direct list initialization: =value[2] {100,200};=

The C++ version is safer: It avoids "narrow conversions", which means
e.g. to implicitly turn a ~float~ value into a ~int~ value.

* The Range-based ~for~ loop

- This loop iterates once for each element in an array. It was
  introduced in C++11.

- General form:
  #+begin_example
  for (dataType rangeVariable : array)
      statement
  #+end_example

- Here, `dataType` is the data type of the `rangeVariable`, which
  receives a different array element during each loop iteration.

- `array` is the array the loop operates on, and `statement` is what
  you want to do in an iteration.

- Example: Use range-based iteration to display the array: 3,6,9.
  #+begin_src C++ :main yes :includes <iostream> :namespaces std :results output :exports both :noweb yes
    int numbers[] {3,6,9};
    for (int val : numbers)  // loop with val over numbers
      cout << val << " ";    // give me each val 
  #+end_src

  #+RESULTS:
  : 3 6 9 

- You can use the ~auto~ key word to infer the data type of the range
  variable:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    int numbers[] {3,6,9};
    for (auto val : numbers)  // compiler will identify int
      cout << val << " ";    
  #+end_src

  #+RESULTS:
  : 3 6 9 

- Example: Display the elements of a ~string~ array.
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> :namespaces std :results output :exports both :noweb yes
    std::string names[] {"Jim", "Joe", "Jane", "Jack"};
    for(std::string name : names) cout << name << endl;

* Modifying an array with a Range-Based ~for~ Loop

- As the range-based loop executes, the range variable receives a copy
  of an array element. To change the contents of an array, the range
  variable needs to be declared as a *reference*.

- What is a reference?
  #+begin_quote
  A reference in C++ is an ALIAS for an existing variable:
  1. It must be initialized when it is declared.
  2. It cannot be changed to refer to something else.
  3. Any operation on the reference affects the original.
  Syntax: ~&~ (address-of-operator)
  #+end_quote

- Code example:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    int x = 10;  // integer variable
    int &ref = x; // ref is a reference variable referencing x
    ref = 20;
    cout << "x = " << x << endl;
  #+end_src

  #+RESULTS:
  : x = 20

- Example: Declare integer array of =SIZE= 5, get values for the array
  from =inputFile= in the =../data= directory, and display the array
  values. Use a range-based ~for~ loop for both iterations.

  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> :namespaces std :results output :exports both :noweb yes
    #include <fstream>  // contains ifstream and ofstream
    // set array SIZE to 5
    const int SIZE {5};
    // declare array `numbers`
    int numbers[SIZE];
    // declare input file
    ifstream inputFile;
    // Get values for the array from input file
    inputFile.open("../data/inputFile");

    for (int &val : numbers)
      inputFile >> val;     // read data from the filestream

    inputFile.close();    
    // Display values in the array
    for (int val : numbers)
      cout << val << " ";  // stream data to stdout
  #+end_src

  #+RESULTS:
  : 101 102 103 104 105 

- Input file:
  #+begin_src bash :results output :exports both
    cd ../data
    echo "101 102 103 104 105" > inputFile
    cat inputFile
  #+end_src

  #+RESULTS:
  : 101 102 103 104 105

- Why does the first loop use =&val= while the second loop uses =val=?
  #+begin_quote
  The first loop modifies the original array: =&val= is alias for
  the element that the loop is working on.

  The second loop only displays the array elements but does not alter
  them.
  #+end_quote

- What's the advantage of range-based loops?
  #+begin_quote
  Easier to read and safer because there is no out-of-bounds possible.
  #+end_quote

- What's the disadvantage of range-based loops?
  #+begin_quote
  When using range-based loops you do not have access to individual
  subscripts.
  #+end_quote
