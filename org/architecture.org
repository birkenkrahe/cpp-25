* 1. Load Balancing (Round Robin)
** Concept
Distributing traffic across multiple servers to prevent overload.
** Data Structure: Vector (~std::vector~)
Teaches: Iteration, Modular Arithmetic, Random Access.
** C++ Implementation
#+begin_src cpp :results output
// 01_load_balancer.cpp
// Demonstrates Round Robin selection using a vector and modulo operator.

#include <iostream>
#include <vector>
#include <string>

class LoadBalancer {
    std::vector<std::string> servers;
    int current_index = 0;

public:
    // Constructor: Initialize with a list of server names
    LoadBalancer(std::vector<std::string> s) : servers(s) {}

    std::string get_server() {
        std::string server = servers[current_index];
        
        // Modulo operator % ensures we wrap around to 0 when we reach the end
        // e.g., if size is 3, index goes: 0 -> 1 -> 2 -> 0 -> ...
        current_index = (current_index + 1) % servers.size();
        
        return server;
    }
};

int main() {
    LoadBalancer lb({"Server A", "Server B", "Server C"});
    
    // Simulate 4 sequential requests
    // Notice how the 4th request wraps back to "Server A"
    for(int i=0; i<4; i++) {
        std::cout << "Request " << i+1 << " handled by: " << lb.get_server() << "\n";
    }
    return 0;
}
#+end_src

#+RESULTS:
: Request 1 handled by: Server A
: Request 2 handled by: Server B
: Request 3 handled by: Server C
: Request 4 handled by: Server A

* 2. Caching
** Concept
Storing the result of expensive operations to speed up future reads.
** Data Structure: Hash Map (~std::unordered_map~)
Teaches: O(1) Lookup, Key-Value pairs.
** C++ Implementation
#+begin_src cpp :results output
// 02_caching.cpp
// Simulates a slow database fetch vs. a fast cache hit using a Hash Map.

#include <iostream>
#include <unordered_map>
#include <string>
#include <thread> // For sleep simulation

// The Cache: Stores Key (User ID) -> Value (Data)
std::unordered_map<std::string, std::string> cache;

std::string get_data(std::string key) {
    // 1. Check Cache (O(1) complexity)
    if (cache.find(key) != cache.end()) {
        return "Cache Hit: " + cache[key];
    }

    // 2. Simulate DB fetch (expensive operation)
    std::cout << "Fetching from DB (Slow operation in progress)...\n";
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    std::string result = "Data for " + key;

    // 3. Store result in Cache for next time
    cache[key] = result;
    return "DB Hit: " + result;
}

int main() {
    std::cout << "--- First Call (Cold Cache) ---\n";
    // This will trigger the "DB fetch"
    std::cout << get_data("user_1") << "\n\n";

    std::cout << "--- Second Call (Warm Cache) ---\n";
    // This will return immediately from the map
    std::cout << get_data("user_1") << "\n";
    return 0;
}
#+end_src

#+RESULTS:
: --- First Call (Cold Cache) ---
: Fetching from DB (Slow operation in progress)...
: DB Hit: Data for user_1
: 
: --- Second Call (Warm Cache) ---
: Cache Hit: Data for user_1

* 3. Content Delivery Network (CDN)
** Concept
Serving static assets from a server geographically closer to the user.
** Data Structure: Hash Map (~std::unordered_map~)
Teaches: Multiple Map logic, Check-then-Fetch patterns.
** C++ Implementation
#+begin_src cpp :results output
// 03_cdn.cpp
// Simulates checking an "Edge" server before falling back to "Origin".

#include <iostream>
#include <unordered_map>
#include <string>

// Origin: The central source of truth (slow/distant)
std::unordered_map<std::string, std::string> origin = {{"img.png", "Image_Bytes_XYZ"}};

// Edge: The local server near the user (fast)
std::unordered_map<std::string, std::string> edge_server;

std::string get_asset(std::string file) {
    // 1. Check Edge Server first
    if (edge_server.count(file)) {
        return "Served from Edge (Fast): " + edge_server[file];
    }

    // 2. Fetch from Origin if missing
    if (origin.count(file)) {
        std::cout << "[!] Not in Edge. Fetching from Origin...\n";
        
        // 3. "Cache" it at the edge for future requests
        edge_server[file] = origin[file]; 
        
        return "Served from Origin: " + origin[file];
    }
    return "404 Not Found";
}

int main() {
    std::cout << "--- User 1 Request (Miss) ---\n";
    std::cout << get_asset("img.png") << "\n\n";
    
    std::cout << "--- User 2 Request (Hit) ---\n";
    std::cout << get_asset("img.png") << "\n";
    return 0;
}
#+end_src

#+RESULTS:
: --- User 1 Request (Miss) ---
: [!] Not in Edge. Fetching from Origin...
: Served from Origin: Image_Bytes_XYZ
: 
: --- User 2 Request (Hit) ---
: Served from Edge (Fast): Image_Bytes_XYZ

* 4. Message Queue
** Concept
Decoupling producers and consumers. The producer doesn't wait for the consumer.
** Data Structure: Queue (~std::queue~) + Mutex
Teaches: FIFO (First-In-First-Out), Concurrency, Locks.
** C++ Implementation
#+begin_src cpp :results output
// 04_message_queue.cpp
// Demonstrates FIFO processing with a standard queue.

#include <iostream>
#include <queue>
#include <mutex>
#include <string>

class MessageQueue {
    std::queue<std::string> q;
    std::mutex mtx; // Ensures thread safety during push/pop

public:
    // PRODUCER: Adds messages to the back of the queue
    void send(std::string msg) {
        std::lock_guard<std::mutex> lock(mtx); // Auto-locks/unlocks scope
        q.push(msg);
        std::cout << "Producer: Enqueued -> " << msg << "\n";
    }

    // CONSUMER: Removes messages from the front of the queue
    void consume() {
        std::lock_guard<std::mutex> lock(mtx);
        if (!q.empty()) {
            std::cout << "Consumer: Processing -> " << q.front() << "\n";
            q.pop(); // Remove from front
        } else {
            std::cout << "Consumer: Queue is empty.\n";
        }
    }
};

int main() {
    MessageQueue mq;
    
    std::cout << "--- Step 1: Producing Tasks ---\n";
    mq.send("Task 1 (Email)");
    mq.send("Task 2 (Log)");
    
    std::cout << "\n--- Step 2: Consuming Tasks ---\n";
    mq.consume(); // Should process Task 1
    mq.consume(); // Should process Task 2
    return 0;
}
#+end_src

#+RESULTS:
: --- Step 1: Producing Tasks ---
: Producer: Enqueued -> Task 1 (Email)
: Producer: Enqueued -> Task 2 (Log)
: 
: --- Step 2: Consuming Tasks ---
: Consumer: Processing -> Task 1 (Email)
: Consumer: Processing -> Task 2 (Log)

* 5. Publish-Subscribe (Pub/Sub)
** Concept
One publisher sends a message to many subscribers.
** Data Structure: Vector of Functions (~std::vector<std::function>~)
Teaches: Function Pointers, Callbacks, Observer Pattern.
** C++ Implementation
#+begin_src cpp :results output
// 05_pub_sub.cpp
// Demonstrates broadcasting events to multiple listeners.

#include <iostream>
#include <vector>
#include <functional>

class PubSub {
    // Stores a list of callback functions
    std::vector<std::function<void(std::string)>> subscribers;

public:
    // Add a new function to the subscriber list
    void subscribe(std::function<void(std::string)> callback) {
        subscribers.push_back(callback);
    }

    // Iterate through all subscribers and call them
    void publish(std::string msg) {
        for (auto& sub : subscribers) {
            sub(msg);
        }
    }
};

// Subscriber Functions
void service_a(std::string msg) { std::cout << "Service A received: " << msg << "\n"; }
void service_b(std::string msg) { std::cout << "Service B received: " << msg << "\n"; }

int main() {
    PubSub channel;
    
    // Register the listeners
    channel.subscribe(service_a);
    channel.subscribe(service_b);
    
    std::cout << "--- Broadcasting 'System Update' ---\n";
    channel.publish("System Update Available");
    return 0;
}
#+end_src

#+RESULTS:
: --- Broadcasting 'System Update' ---
: Service A received: System Update Available
: Service B received: System Update Available

* 6. API Gateway

** Data Structure: Routing Logic (Can be upgraded to a Trie)
Teaches: String parsing, Branching logic.
** C++ Implementation

#include <string>

* 7. Circuit Breaker
** Concept
Stop calling a failing service to prevent cascading failures.
** Data Structure: State Machine (Enum)
Teaches: Enums, State Management, Threshold logic.
** C++ Implementation
#+begin_src cpp :results output
// 07_circuit_breaker.cpp
// Simulates a state machine that 'trips' after too many failures.

#include <iostream>

class CircuitBreaker {
    enum State { CLOSED, OPEN }; // CLOSED = Good, OPEN = Bad
    State state = CLOSED;
    int failures = 0;
    int threshold = 3;

public:
    void call_service() {
        // 1. Safety Check: If Open, fail fast without trying
        if (state == OPEN) {
            std::cout << "[BLOCK] Circuit is OPEN. Request blocked locally.\n";
            return;
        }

        // 2. Simulate attempting the service (Assume it fails for demo)
        failures++;
        std::cout << "Service Call Failed... (Count: " << failures << ")\n";

        // 3. Check if we reached the limit
        if (failures >= threshold) {
            state = OPEN;
            std::cout << "!!! Threshold reached. Circuit is now OPEN !!!\n";
        }
    }
};

int main() {
    CircuitBreaker cb;
    
    std::cout << "--- Allowing 3 Failures ---\n";
    cb.call_service(); // Fail 1
    cb.call_service(); // Fail 2
    cb.call_service(); // Fail 3 -> State changes to OPEN
    
    std::cout << "\n--- 4th Attempt (Should be blocked) ---\n";
    cb.call_service(); 
    return 0;
}
#+end_src

#+RESULTS:
: --- Allowing 3 Failures ---
: Service Call Failed... (Count: 1)
: Service Call Failed... (Count: 2)
: Service Call Failed... (Count: 3)
: !!! Threshold reached. Circuit is now OPEN !!!
: 
: --- 4th Attempt (Should be blocked) ---
: [BLOCK] Circuit is OPEN. Request blocked locally.

* 8. Service Discovery
** Concept
Automatically detecting devices/services on a network.
** Data Structure: Map (~std::map~ or ~std::unordered_map~)
Teaches: Registry patterns, Key-Value lookup.
** C++ Implementation
#+begin_src cpp :results output
// 08_service_discovery.cpp
// Using a Map to act as a "Phonebook" for services.

#include <iostream>
#include <map>
#include <string>

// The Registry: Name -> IP Address
std::map<std::string, std::string> registry;

void register_service(std::string name, std::string ip) {
    registry[name] = ip;
    std::cout << "Registered '" << name << "' at " << ip << "\n";
}

std::string discover(std::string name) {
    // Check if the key exists in the map
    if (registry.count(name)) return registry[name];
    return "Unknown Service";
}

int main() {
    // Service startup phase
    register_service("Auth", "10.0.0.1");
    register_service("Payment", "10.0.0.2");

    std::cout << "\n--- Client Lookup ---\n";
    std::cout << "Looking up 'Auth': " << discover("Auth") << "\n";
    std::cout << "Looking up 'Logs': " << discover("Logs") << "\n";
    return 0;
}
#+end_src

#+RESULTS:
: Registered 'Auth' at 10.0.0.1
: Registered 'Payment' at 10.0.0.2
: 
: --- Client Lookup ---
: Looking up 'Auth': 10.0.0.1

* 9. Sharding
** Concept
Splitting a large database into smaller chunks based on a key (e.g., ID).
** Data Structure: Multiple Vectors
Teaches: Hashing (Modulo operator) for distribution.
** C++ Implementation
#+begin_src cpp :results output
// 09_sharding.cpp
// Distributing data to different containers (Shards) based on ID parity.

#include <iostream>
#include <vector>
#include <string>

// We simulate 2 separate "Servers" using vectors
std::vector<std::string> shard1; // For EVEN IDs
std::vector<std::string> shard2; // For ODD IDs

void insert_data(int id, std::string data) {
    // Sharding Logic: ID % 2
    if (id % 2 == 0) {
        shard1.push_back(data);
        std::cout << "[Shard 1] Saved " << data << " (ID: " << id << ")\n";
    } else {
        shard2.push_back(data);
        std::cout << "[Shard 2] Saved " << data << " (ID: " << id << ")\n";
    }
}

int main() {
    std::cout << "--- Inserting Data ---\n";
    // ID 100 is Even -> Goes to Shard 1
    insert_data(100, "User_Alice");

    // ID 101 is Odd -> Goes to Shard 2
    insert_data(101, "User_Bob");
    
    // ID 102 is Even -> Goes to Shard 1
    insert_data(102, "User_Charlie");
    return 0;
}
#+end_src

#+RESULTS:
: --- Inserting Data ---
: [Shard 1] Saved User_Alice (ID: 100)
: [Shard 2] Saved User_Bob (ID: 101)
: [Shard 1] Saved User_Charlie (ID: 102)

* 10. Rate Limiting
** Concept
Restricting the number of requests a user can make in a given timeframe.
** Data Structure: Counters & Timers
Teaches: Time handling (~std::chrono~), conditional logic.
** C++ Implementation
#+begin_src cpp :results output
// 10_rate_limiter.cpp
// Simulates a Token Bucket algorithm.

#include <iostream>
#include <chrono>
#include <thread>

class RateLimiter {
    int tokens;
    int max_tokens;
    std::chrono::steady_clock::time_point last_refill;

public:
    RateLimiter(int max) : tokens(max), max_tokens(max) {
        last_refill = std::chrono::steady_clock::now();
    }

    bool allow_request() {
        auto now = std::chrono::steady_clock::now();
        
        // Logic: If 1 second has passed, refill the bucket
        if (std::chrono::duration_cast<std::chrono::seconds>(now - last_refill).count() >= 1) {
            tokens = max_tokens;
            last_refill = now;
            std::cout << ">>> (1 second passed: Tokens Refilled) <<<\n";
        }

        if (tokens > 0) {
            tokens--;
            return true; // Allowed
        }
        return false; // Blocked
    }
};

int main() {
    RateLimiter limiter(1); // Limit: 1 request per second
    
    std::cout << "Request 1: " << (limiter.allow_request() ? "Allowed" : "Blocked") << "\n";
    std::cout << "Request 2: " << (limiter.allow_request() ? "Allowed" : "Blocked") << "\n";
    
    // Wait so token refills
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Request 3: " << (limiter.allow_request() ? "Allowed" : "Blocked") << "\n";

    return 0;
}
#+end_src

#+RESULTS:
: Request 1: Allowed
: Request 2: Blocked
: Request 3: >>> (1 second passed: Tokens Refilled) <<<
: Allowed

* 11. Consistent Hashing
** Concept
Distributing data across nodes such that adding/removing a node minimizes movement.
** Data Structure: Ordered Map / BST (~std::map~)
Teaches: Tree Maps (Red-Black Tree), Binary Search (~upper_bound~), Circular logic.
** C++ Implementation
#+begin_src cpp :results output
// 11_consistent_hashing.cpp
// Using an Ordered Map to simulate a "Ring" of servers.

#include <iostream>
#include <map>
#include <string>

class ConsistentHash {
    // std::map is sorted by Key (int) automatically.
    // This represents the ring: 0...100...200...MAX
    std::map<int, std::string> ring; 

public:
    void add_node(int hash, std::string name) {
        ring[hash] = name;
    }

    std::string get_node(int key_hash) {
        if (ring.empty()) return "";

        // upper_bound returns an iterator to the first element *greater* than key_hash.
        // This simulates moving clockwise on the ring.
        auto it = ring.upper_bound(key_hash);

        // If we reach the end of the map, wrap around to the beginning (Circle behavior)
        if (it == ring.end()) {
            return ring.begin()->second;
        }
        return it->second;
    }
};

int main() {
    ConsistentHash ch;
    ch.add_node(100, "Node A");
    ch.add_node(200, "Node B");

    std::cout << "Key 150 -> " << ch.get_node(150) << " (Next highest is 200)\n"; 
    std::cout << "Key 250 -> " << ch.get_node(250) << " (Wraps around to 100)\n"; 
    return 0;
}
#+end_src

#+RESULTS:
: Key 150 -> Node B (Next highest is 200)
: Key 250 -> Node A (Wraps around to 100)

* 12. Auto Scaling
** Concept
Adding or removing resources based on current load.
** Data Structure: Vector (Dynamic Array)
Teaches: Dynamic resizing (~push_back~, ~pop_back~).
** C++ Implementation
#+begin_src cpp :results output
// 12_auto_scaling.cpp
// Simulates a monitoring loop that adds/removes resources based on traffic.

#include <iostream>
#include <vector>

// Represents active CPU cores
std::vector<int> cpu_cores = {1}; // Start with 1 core

void monitor(int traffic_load) {
    // If load > 80, Add a core
    if (traffic_load > 80) {
        cpu_cores.push_back(1);
        std::cout << "[Alert] High Traffic (" << traffic_load << ")! Scaled UP to " << cpu_cores.size() << " cores.\n";
    } 
    // If load < 10, Remove a core (but keep at least 1)
    else if (traffic_load < 10 && cpu_cores.size() > 1) {
        cpu_cores.pop_back();
        std::cout << "[Alert] Low Traffic (" << traffic_load << "). Scaled DOWN to " << cpu_cores.size() << " cores.\n";
    } 
    else {
        std::cout << "[Info] Traffic Stable (" << traffic_load << "). Cores active: " << cpu_cores.size() << "\n";
    }
}

int main() {
    monitor(90); // Trigger Scale Up
    monitor(95); // Trigger Scale Up Again
    monitor(5);  // Trigger Scale Down
    return 0;
}
#+end_src

#+RESULTS:
: [Alert] High Traffic (90)! Scaled UP to 2 cores.
: [Alert] High Traffic (95)! Scaled UP to 3 cores.
: [Alert] Low Traffic (5). Scaled DOWN to 2 cores.

* Glossary

| Data Structure | Standard C++ STL    | Architecture Assignment Idea |                                                                     |
|----------------+---------------------+------------------------------+---------------------------------------------------------------------|
| *Hash Table*     | ~std::unordered_map~  | *Caching / Sharding*           | Create a cache that simulates a slow DB fetch.                      |
| *Queue*          | ~std::queue~          | *Rate Limiting*                | Implement a sliding window log using a queue of timestamps.         |
| *Balanced BST*   | ~std::map~            | *Consistent Hashing*           | Map users to servers on a ring; add a server and see how many move. |
| *Vector*         | ~std::vector~         | *Load Balancing*               | Implement Round-Robin iteration over a list of servers.             |
| *Heap*           | ~std::priority_queue~ | *Least-Connections LB*         | Always pick the server with current minimum connections (O(1)).     |
| *Trie*           | *(Custom Class)*      | *API Gateway*                  | Route paths like /api/v1/user using a prefix tree.                  |
