* Basic C++ Programming Elements

- C++ is a superset of the C programming language.
- It deals efficiently with hardware at the level of addresses.
- Its principal enhancement is the object-oriented ~class~ concept.
- Classes are user-defined types with:
  + Guaranteed initialization
  + Implicit type conversion
  + Control of memory management
  + Operator overloading
  + Polymorphism.
- A ~class~ can hide its underlying data to conceal implementation.
- Users can conceptualize the ~class~ through a well-defined interface.
- Classes enable programmers to break an application up into objects.
- The resulting programs are easier to understand and to maintain.

* A Simple C++ Program

- *Steps:*
  1) Create a C++ source file with an editor and save it (.cpp)
  2) Run a compiler to create a machine code interpretation (.o)
  3) Run a linker to include libraries and produce an executable.
  4) Run the executable to complete the task programmed.

- *How can you visualize the linker?* Normally, the compiler invokes the
  linker automatically, and you don't see the object code.
  #+begin_quote
  Check the compiler's *man* page, ~gcc(1)~: "When you invoke GCC, it
  normally does preprocessing, compilation, assembly and linking.  The
  'overall options' allow you to stop this process at an intermediate
  stage.  For example, the ~-c~ option says not to run the linker.  Then
  the output consists of object files output by the assembler."
  #+end_quote

- *Example:* Minimal C++ program
  #+begin_src bash :results output :exports both
    echo "int main(){}" > main.cpp
    cat main.cpp
    g++ main.cpp -c
    ls -l main*
    file main.o
    g++ main.o -o main
    ./main
    echo $? # exit status of the most recently executed command
  #+end_src

* Program elements

1) Two *header* files are included. Their location is in the
   ~$PATH~. Where are these files located? What do they do?
   #+begin_src bash :results output :exports both
     find /usr/include /usr/local/include \
          -type f \( -name 'cstdlib' -o -name 'iostream' \) | xargs file
   #+end_src
   #+begin_quote
   - ~iostream~ provides definitions for input (~cin~) and output
     (~cout~).
   - ~cstdlib~ provides some standard system definitions like
     ~EXIT_SUCCESS~, a macro that usually expands to ~0~.
   #+end_quote

2) The initial entry point for C++ programs is the *function*
   ~main~. In this case ~int main()~ is a function that takes no
   (~void~) arguments and has an integer (~int~) ~return~.

   The general ~main~ function may be called with command-line
   arguments: ~main(int argc, char *argv[])~.

3) The *function body* is enclosed in curly braces ~{ }~. They define
   a *scope*, or a region of memory: Variables go into and out of
   scope.

4) The program terminates when the ~return~ statement is
   executed. The constant (macro) ~EXIT_SUCCESS~ is defined to be 0
   in ~cstdlib~.

5) The output operator ~<<~ prints a string to the standard output
   stream (~stdout)~, for example the screen.

6) The input operator ~>>~ obtains the variables from standard input
   (~stdin)~, for example the keyboard. There is also standard error
   (~stderr~) where error output is written.

7) These data streams are denoted ~std::cout~, ~std::cin~, and ~std:cerr~,
   respectively. The prefix ~std::~ indicates that they come from the
   standard library.

8) To inform the compiler that we wish to use objects from the
   standard library, we can write ~using namespace std~ at the top
   instead:

   #+begin_src C++
     #include <iostream>
     using namespace std;

     int main() {
       cout << "Hello" << endl; // `std::` is not needed
     }
   #+end_src

   #+RESULTS:
   : Hello

9) You can put most of the previous code into the Org-mode code block
   header (and define it as a macro in ~org-structure-template-alist~).

   #+begin_src C++ :main yes :includes <iostream> :namespaces std
     cout << "Hello" << endl; // `std::` is not needed
   #+end_src

   #+RESULTS:
   : Hello

10) The output statement does not produce a new line. It can be added
    either with ~std::endl~, or with C's ~'\n'~.

* Characters

- A ~char~ is typically 8-bits (1 byte, 1 word)

- A *literal* is a constant value. Character literals are enclosed in
  single quotes: ~'a'~, '+'~ etc.

- There is a number of special character literals:
  #+name: special characters
  | ~'\0'~ | null                 |
  | ~'\b'~ | backspace            |
  | ~'\t'~ | tab                  |
  | ~'\n'~ | newline              |
  | ~'\r'~ | carriage return (CR) |
  | ~'\"'~ | double quote         |
  | ~'\''~ | single quote         |
  | ~'\\'~ | backslash            |

- The null character ~'\0'~ is used to indicate the end of a string of
  characters.

- The function =int(c)= returns the (ASCII) integer value associated
  with a character variable =c=.

- The function =char(a)= returns the character literal associated with

* Integers

- Integers come in three sizes: ~short [int]~, ~int~, and ~long [int]~.

- The suffix ~l~ or ~L~ can be added to indicate a ~long~ integer.

- Octal (base 8) constants are prefixed with ~0~.

- Hexadecimal (base 16) constants are prefixed with ~0x~.

- When declaring a variable, you can define it (give it a name), or
  assign (~=~) an initial value. If no initial value is given, the value
  is unpredictable/undefined.

- Variable names may not have a digit as first character, and contain
  only ~_~ (underscore) as special character. In C++, you will see more
  "camelCase" variables rather than "under_score" as in C.

- Examples:
  #+name: variables
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results none :exports both :noweb yes

    int octalNumber = 0400; // 400 (base 8) = 256 (base 10) = 4 * 8^2
    char newlineChar = '\n';
    long BIGnumber = 31459265L;
    short _aSTRANGE__1234_variABlE_NaMe = 42;
  #+end_src

- C++ does not specify the exact number of bits in each type but a
  ~short~ is at least 16 bits, and a ~long~ is at least 32 bits long.

- Explanation:
  #+begin_quote
  ~static_cast~ is a compile-time cast in C++. It converts between types
  in a type-safe and explicit way: =static_cast<Day>(input)= converts
  the ~int~ (user input from ~cin~) to the custom ~enum~ =Day=.

  C++ will not implicitly convert ~int~ to ~enum~ to avoid silently
  assigning an invalid or out-of-range value.

  =static_cast<Day>(input)= tells the compiler: "I understand the risk,
  go ahead." The shorter =Day today = input= is not allowed.
  #+end_quote

- Is this allowed in Python?
  #+begin_quote
  Python is not statically but dynamically typed. You can just call
  =Day(input)= or =Day['THU']= and Python enforces validity.
  #+end_quote

  #+begin_example python
  from enum import Enum

  class Day(Enum):
      SUN = 1
      MON = 2
      TUE = 3
      WED = 4
      THU = 5
      FRI = 6
      SAT = 7

  val = input("Enter today's day (SUN, MON, ..., SAT): ").upper()
  try:
      today = Day[val]
      if today in (Day.SAT, Day.SUN):
          print("It's the weekend!")
      else:
          print("It's a weekday.")
  except KeyError:
      print("Invalid day name.")
  #+end_example

* Floating-point

- Single-precision (32-bit) and double-precision (64-bit) are stored
  in ~float~ and ~double~ variables.

- The exact number of bits in each of these types is left undefined
  (down to machine architecture). By default, floating point literals
  like ~3.1459~ are of type ~double~.

- Scientific exponential notation can be specified using ~e~ or ~E~ to
  separate the mantissa (the leading numbers) from the exponent:
  =3.14E5= is 3.14 \times 10^{5}.

- To force a literal to be a ~float~, add the suffix ~f~ or ~F~ as in =2.0f=.

* Pointers

- What is a *pointer*?
  #+begin_quote
  A pointer is a *variable* =p= that holds the value of an *address* to
  another variable =x=: =x = *p= and =p = &x=. This other variable can also
  be a pointer (then the original pointer is a double pointer).
  #+end_quote

- Two operators are used to manipulate pointers:
  1) The *address-of* operator ~&~: =int* p = &x= points to the address of =x=
     in memory.
  2) The *dereferencing* or *indirection* operator ~*~: =*p = *(&x) = x=
     contains the value of =x=.

- Pointer manipulation is powerful because it grants direct control
  over memory. This leads to very efficient, dynamic data structures.

- Pointer-based structures can grow and shrink at run-time, while
  arrays are fixed-size (though there are variable-length arrays).

- Size determination at run-time means that larger datasets can be
  accommodated when the program is executed. Their size does not have
  to be anticipated when the program is written.

* Arrays

- An *array* is a fixed-size collection of elements of the same type.
  Given any type ~T~ and a constant =N=, a variable of type =T[N]= holds
  an array of =N= elements, each of type ~T~.

- Array *elements* are accessed by *index*, ranging from =0= to =N-1=.

- Examples:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both
    double foo[5];     // 5-element array of doubles
    int bar[10];       // 10-element array of integers

    foo[4] = 2.5;       // assign value to the 5th (last) element of foo
    bar[2] = 4;         // assign value to the 3rd element of bar

    cout << foo[bar[2]]; // prints foo[4], i.e. 2.5
  #+end_src

  #+RESULTS:
  : 2.5

- Once declared, the number of elements in a C or C++ array is *fixed*.

- *What about VLAs?* C introduced *Variable Length Arrays* (VLAs) in
  C99. VLAs allow array sizes to be determined at *runtime*, but the
  size remains *fixed after declaration*.  VLAs are optional in C11 and
  removed in C23. *C++ does not support VLAs.*

- C++ provides no built-in run-time checking for out-of-bounds
  indexing.[fn:1] The ~vector~ type of the C++ Standard Template Library
  (STL) provides a more comfortable array type (with run-time index
  checking and the ability to dynamically change the array's size).

- How is a *two-dimensional* array *implemented*?
  #+begin_quote
  A 2-dim array is implemented as an array of arrays: =A[15][30]=
  declares =A= to be an array of 30 objects, each of which is an array
  of 15 integers.
  #+end_quote

- How is a two-dimensional array *indexed*?
  #+begin_quote
  A two-dimensional array =A[M][N]= is indexed as =A[i][j]= with =i= \in
  [0,M-1] and =j= \in [0,N-1].
  #+end_quote

  #+end_quote

* *Bonus: Padding vs. packing in C/C++*

- Packing is used in networking protocols to match machine formats.

  | Concept   | Padding                               | Packing                      |
  |-----------+---------------------------------------+------------------------------|
  | *What*      | Automatic insertion of unused bytes   | Manual removal               |
  | *Why*       | Align data for efficient CPU access   | Save memory                  |
  | *How*       | Compiler-based on alignment rules     | Done via compiler directives |
  | *Result*    | Larger struct size with faster access | Smaller struct size (slower) |
  | *Portable?* | Yes (default behavior)                | Non-portable                 |

- Code example:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    // No packing but padding
    struct A {
      char c;   // 1 byte
      int i;    // 4 bytes â†’ aligned at 4
    }; // size = 8 (3 bytes padding after c)

    #pragma pack(1) // BEGIN compiler directive
    struct B {
      char c;
      int i;
    }; // size = 5 (no padding, but slower access)
    #pragma pack()  // END compiler directive

    A a;
    B b;
    cout << "Size of A: " << sizeof(A) << endl
    << "Size of B: " << sizeof(B) << endl;
  #+end_src

  #+RESULTS:
  : Size of A: 8
  : Size of B: 5

- In the last example, reordering =A= would not help because an ~int~ and
  a ~char~ always have to be padded by 3 bytes to satify alignment
  rules.

- The operator ~new~ dynamically allocates the correct amount of storage
  from an object of a given type from the free store and returns a
  pointer to this object.

- What is the value of this pointer?

  memory. Pointers can point to any data type, including other
  pointers, or individuals cells in an array.

  p->name = "John Smith";

  #+begin_quote
  1. *Stack allocation*: =p= is an *object* of type =Passenger= stored on the
     *stack*. Its members are accessed with the dot operator. It is
     automatically destroyed when it goes out of scope.

  2. *Heap allocation*: =q= is a *pointer* to a =Passenger= allocated on the
     *heap*. Its members are accessed with the arrow operator. It must
     be manually deleted but the programmer controls its lifetime.
  #+end_quote

- What happens if one does not ~delete~ dynamically allocated memory?
  #+begin_quote
  C++ does not have *garbage collection*, and all dynamically allocated
  objects must be deleted manually. Otherwise one gets a memory leak.
  #+end_quote

- To free the memory allocated to a ~new~ object, use
  ~delete~. Afterwards, the pointers must not be used anymore because it
  is now dangling freely, without a specific target (though it still
  stores an address). To tie lose ends, assign a ~nullptr~ to it.

- Example: Use ~delete~ to delete a passenger, then print the pointer's
  address, assign a ~nullptr~ and print it again.

  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes

    p->name = "Kitty Malone"; // assigns Passenger name

    cout << "Passenger name: " << p->name << endl;
    cout << "Pointer address before deletion: " << p << endl;

    delete p; // free memory of new Passenger
    cout << "Pointer address after deletion: " << p << endl;

    p = nullptr; // make pointer into a null pointer
    cout << "Pointer address after nullptr: " << p;

  #+end_src

  #+RESULTS:
  : Passenger name: Kitty Malone
  : Pointer address before deletion: 0x5fd429c21eb0
  : Pointer address after deletion: 0x5fd429c21eb0
  : Pointer address after nullptr: 0

- What would happen if we would print =p->name= after the ~delete p~
  operation?
  #+begin_quote

* Named Constants, literals, ~typedef~

- What's the difference between a *literal* and a *constant*?
  #+begin_quote
  - Literals are raw values, constants are named, typed, immutable
    variables.
  - Constants may be used anywhere where literals may be used as well,

  | *Type*        | Implicit (type inferred) | Declared w/explicit type |
  | *Purpose*     | Provide raw data         | Readable and reusable    |
  | *Modifiable?* | No                       | No                       |
  #+end_quote

* Scope

- A group of C++ statements enclosed in curly braces ~{...}~ define a
  block. Variables and types declared within the block are *local*.

- Variables and types declared outside of any block are *global* and are
  accessible from anywhere in the program.

- The portions of a program from which a given name is accessible are
  called its *scope*.

- Example: Two variables of the same name defined within nested blocks

  #+begin_src C++ :main no :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    const int CAT = 1;

    int main() {
      const int CAT = 2;
      cout << CAT;
      return EXIT_SUCCESS;
    }
    int dog = CAT; // dog = 1 (from the global CAT)
  #+end_src

  #+RESULTS:
  : 2

- It is best to avoid global variables to avoid errors.

* Using namespaces

- Some operations need global objects, e.g. ~cout~, the system's
  standard output stream object.

- A ~namespace~ allows a group of related names to be defined in one
  place, to organize global objects into natural groups.

- Example: A namespace with two variables
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    namespace myglobals {
      int cat;
      string dog = "wuff";
    }

- The *fully qualified name* of a ~namespace~ object uses ~::~, for example
  =myglobals::cat= refers to the copy of =cat= in the =myglobals= ~namespace~.

- ~cin~ and ~cout~ are in the ~std~ namespace. Their fully qualified names
  are ~std::cin~ and ~std::cout~.

- To avoid having to enter the ~namespace~ specifier, we can employ
  ~using~ ahead of the first use:
  #+begin_src C++ :main no :includes <iostream> <string> :results output :noweb yes

    using std::cout;  // make only std::cout accessible

    namespace myglobals {
      int cat;
      string dog = "wuff";

    using namespace myglobals;

    int main() {
      cout << dog;
      return 0;
    }
  #+end_src

  #+RESULTS:
  : wuff

- In the example, ~std::string~ and ~std::cout~ are "brought into scope"
  with ~using~. All of =myglobals= variables are brought into scope.

* Bitwise operators

- Bitwise operators act on the representation of numbers as binary bit
  strings. They can be applied to any integer type resulting in an
  integer type.

- The operators are:
  #+attr_html: :width 400px :float nil:
  [[../img/bitwise.png]]

- *Bitwise complement (=~exp=)*

  - Example: =~5= -> =-6=
  - Explanation: Inverts all bits of 5 (00000101 -> 11111010 in 8-bit,
    which is -6 in *two's complement*[fn:3]).
  - Code example:
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "~5 -> " << ~5 << endl;

      int a = 0b00000101;
      cout << "Original: " << " NOT(" << bitset<8>(a) << ") -> " << bitset<8>(~a);
    #+end_src

    #+RESULTS:
    : ~5 -> -6
    : Original:  NOT(00000101) -> 11111010

- *Bitwise AND (=exp & exp=)*

  - Example: =5 & 3= -> =1=
  - Explanation: 0101 & 0011 = 0001
  - Code example:
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "5 & 3 -> " << (5 & 3) << endl;

      int a = 0b00000101, b = 0b00000011;
      cout << "Original: " << bitset<8>(a) << " AND " << bitset<8>(b)
      << " -> " << bitset<8>(a & b);
    #+end_src

    #+RESULTS:
    : 5 & 3 -> 1
    : Original: 00000101 AND 00000011 -> 00000001

- *Bitwise XOR (exp ^ exp)*
  - Example: =5 ^ 3= -> =6=
  - Explanation: 0101 ^ 0011 = 0110
  - Code example:
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "5 ^ 3 -> " << (5 ^ 3) << endl;

      int a = 0b00000101, b = 0b00000011;
      cout << "Original: " << bitset<8>(a) << " XOR " << bitset<8>(b)
      << " -> " << bitset<8>(a ^ b);
    #+end_src

    #+RESULTS:
    : 5 ^ 3 -> 6
    : Original: 00000101 XOR 00000011 -> 00000110

- *Bitwise OR (exp | exp)*
  - Example: =5 | 3= -> =7=
  - Explanation: 0101 | 0011 = 0111
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "5 | 3 -> " << (5 | 3) << endl;

      int a = 0b00000101, b = 0b00000011;
      cout << "Original: " << bitset<8>(a) << " OR " << bitset<8>(b)
      << " -> " << bitset<8>(a | b);
    #+end_src

    #+RESULTS:
    : 5 | 3 -> 7
    : Original: 00000101 OR 00000011 -> 00000111

- *Left shift (exp1 << exp2)*
  - Example: =5 << 1= -> =10=
  - Explanation: 00000101 becomes 00001010 (multiplies by 2)
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "5 << 1 -> " << (5 << 1) << endl;

      int a = 0b00000101, b = 0b00000001;
      cout << "Original: " << bitset<8>(a) << " << " << bitset<8>(b)
      << " -> " << bitset<8>(a << b);
    #+end_src

    #+RESULTS:
    : 5 << 1 -> 10
    : Original: 00000101 << 00000001 -> 00001010

- *Right shift (exp1 >> exp2)*
  - Example: =5 >> 1= -> =2=
  - Explanation: 00000101 becomes 00000010 (divides by 2)
    #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
      cout << "5 >> 1 -> " << (5 >> 1) << endl;

      int a = 0b00000101, b = 0b00000001;
      cout << "Original: " << bitset<8>(a) << " >> " << bitset<8>(b)
      << " -> " << bitset<8>(a >> b);
    #+end_src

    #+RESULTS:
    : 5 >> 1 -> 2
    : Original: 00000101 >> 00000001 -> 00000010

- Note: The left bitwise shift operator (~<<~) always fills with
  zeros. How the right bitwise shift operator (~>>~) fills depends on a
  variable's type: If the left operand of a right shift is *unsigned*,
  the shift fills with zeros, and otherwise the right shift fills with
  the number's sign bit (0 for positive, 1 for negative numbers):
  #+begin_src C++ :main yes :includes <bitset> <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    unsigned int a = -0b00010100, b = 0b00000001;
    cout << "Original: " << bitset<8>(a) << " >> " << bitset<8>(b)
    << " -> " << bitset<8>(a >> b);
  #+end_src

  #+RESULTS:
  : Original: 11101100 >> 00000001 -> 11110110

* Explicit cast operators

- Casting can be dangerous. For example, casting from =short= to =int= is
  harmless, but casting from =double= to =int= implies truncation. Casting
  from =double*= to =char*= is dangerous because pointers vary by machine.

- To enable *portability*, C++ provides safe explicit casting operators,
  ~static_cast~, ~dynamic_cast~, ~const_cast~, and ~reinterpret_cast~.

- *Static casting* is made between two related types - numbers to
  numbers, or pointers to pointers:
  =static_cast<target_type>(expression)=:

  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    double d1 = 3.2;
    double d2 = 3.9999;
    int i1 = static_cast<int>(d1);
    int i2 = static_cast<int>(d2);

- Safe explicit casting operators should be used whenever a
  potentially unsafe operation takes place.

- Why would one ever cast from ~double~ to ~int~? For example when only
  whole numbers are needed (pixel indexing in graphics, loop bounds,
  or integer-only APIs, because integer operations are much faster).

* Implicit casting

- An *implicit cast* is performed when no explicit cast has been
  requested. For example when numbers of different types are involved,
  the compiler automatically casts towards the stronger type.

- Example:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    int i = 3;
    double d = 4.8;
    double d3 = i / d; // implicit cast to <double>
    int i3 = d3; // implicit cast to <int> with potential warning

    cout << "i = " << i << endl
    << "d = " << d << endl
    << "i/d = " << d3 << endl
    << "i = d -> " << i3 << endl;
  #+end_src

  #+RESULTS:
  : i = 3
  : d = 4.8
  : i/d = 0.625
  : i = d -> 0

- General rule: Play it safe (cast explicitly).

* Argument passing

- By default, arguments are passed *by value*: A copy of the argument is
  made and passed to the function. The original argument in the
  calling program is not altered.

- To modify one of its arguments, it needs to be a *reference type*:
  now, any modifications made to it modify the original argument in
  the calling program.

- Example: the function =f= returns no value (~void~) and passes one
  argument by value, the other one by reference. Inside =f=, both
  arguments are incremented and printed.
  #+name: function
  #+begin_src C++ :results none
    void f(int value, int& ref) {
      value++;
      ref++;
      cout << "value in f = " << value << endl
           << "ref in f =   " << ref   << endl;
    }
  #+end_src

- In ~main~, the function is called on two integer arguments, and the
  resulting values are printed:
  #+begin_src C++ :results output :noweb yes
    #include <iostream>
    using namespace std;

    <<function>>

    int main() {
      int cat = 1;
      int dog = 1;
      f(cat,dog); // pass cat by value, dog by ref
      cout << "cat = " << cat << endl
           << "dog = " << dog << endl;
      return 0;
     }
  #+end_src

  #+RESULTS:
  : value in f = 2
  : ref in f =   2
  : cat = 1
  : dog = 2

- Reference arguments achieve the same result as passing the address
  of the argument (as a pointer), with less notational effort.
  #+begin_src C++ :main no :includes <iostream> <cstdlib> :namespaces std :results output :exports both :noweb yes
    void f2(int value, int* ptr) {
      value++;
      (*ptr)++; // increment dereferenced pointer value
      cout << "value in f = " << value << endl
           << "*ptr in f =  " << *ptr   << endl;
    }
    int main() {
      int cat = 1;
      int dog = 1;
      f2(cat,&dog); // pass cat by value, dog by address
      cout << "cat = " << cat << endl
           << "dog = " << dog << endl;
      return 0;
    }
  #+end_src

  #+RESULTS:
  : value in f = 2
  : *ptr in f =  2
  : cat = 1
  : dog = 2

* Classes
#+attr_html: :width 400px :float nil:
#+caption: Principles of Object-Oriented Programming (OOP)
[[../img/oop.png]]

- Classes are the way in C++ to define new types complete with
  associated functions and operators (*abstraction*).

- By restricting access to members, properties for a class's use can
  be separated from details needed for its implementation
  (*encapsulation*).

- Classes are the foundation of the Object-Oriented Programming (OOP)
  approach, including concepts like *polymorphism* and *inheritance*.

- Bjarne Stroustrup's first version of C++ was simply called "C with
  Classes". This development then gained a momentum of its own.
  
* Class structure

- What is a ~class~?
  #+begin_quote
  A ~class~ consists of member variables (data/attributes) and member
  functions (methods). Variables may be of any type, and may be
  classes themselves. Methods act on the data defining behavior.
  #+end_quote

- How is ~class~ data access controlled?
  #+begin_quote
  + Members that are ~public~ are accessible outside the ~class~.
  + Members that are ~private~ are accessibly only from within.
  + Exceptions: ~protected~ access and ~friend~ functions (see later).
  + By convention, as a matter of style, ~public~ members are listed
    first. The default (no attribute set) means all members are
    ~private~.
  #+end_quote

- Example: The =Counter= ~class~ implements a counter stored in the
  ~private~ integer variable =count=. Three methods initialize (=Counter=),
  access (=getCount=), and increase (=increaseBy=) the counter's value.

  We name the code block [[Counter declaration]] for later use. Note the block header
  which only compiles the ~class~ for syntax checking.

  #+name: Counter declaration
  #+begin_src C++ :results none
    class Counter {
    public:
      Counter();
      int getCount();
      void increaseBy(int x);
    private:
      int count;
    };
  #+end_src

- What else is needed besides the declaration?
  #+begin_quote
  The methods are declared but not defined. They could be used but
  won't do anything. At this point, you cannot even create a =Counter=,
  because the default constructor =Counter()= is empty. A ~main~ program
  with the statement =Counter cnt;= will fail with a linking error.
  #+end_quote

- How can the methods be defined?
  #+begin_quote
  They can be defined alongside the ~class~ declaration, or separately
  (below: [[Counter]]). When defining separately, the methods have to be
  added to the *namespace* of the class with: =Counter::=
  #+end_quote

* Destructors spell desaster

- Constructors create ~class~ objects, destructors destroy them. If the
  ~new~ operator is used, the destructor is called using ~delete~ (unless
  a *smart pointer* is used).

- Example: The following =Vect= class in [[Vector]] stores a vector by
  dynamically allocating an array of integers. The array of length
  =size= is referenced by the pointer =data=. The constructor allocates
  the array, the destructor frees it:

  #+name: Vector
  #+begin_src C++ :main no :includes :results none :noweb yes
    class Vect { // class declaration

    public:
      Vect(int n=10); // constructor declaration
      ~Vect(); // destructor declaration
    private:
      int* data; // pointer to array head
      int  size; // length of array
    };

    Vect::Vect(int n) { // constructor
      size = n; // length of array
      data = new int[n]; // allocate n integer
    }

    Vect::~Vect() { // destructor
      delete [] data;
    }
  #+end_src

- Note that memory that was allocated with ~new []~ must be de-allocated
  with ~delete []~ so that all of the =n= array elements are
  destroyed. Destructors never have to be invoked explicitly

- Note that the default constructor creates an array of size 10. The
  default parameter value needs to be only declared.

- *Explanation*: All three vectors a,b,c share the same 100-element
  array. =a= is a =Vect= object of 100 elements, and =c= is a default object
  of 10 elements. Since there is no copy constructor, =Vect b = a=
  copies each member of =a= to =b=, by pointers: =b.data = a.data=. This is
  called a *shallow copy*. It gets worse: No assignment operator for
  =Vect= was provided, so the statement c = a also shallow copies a to c
  (only pointers are copied). At the same time, the pointer to =c= is
  lost (memory leak). All objects have members pointing to the same
  array in the *free store* (aka *heap memory*) - if one was deleted for
  example, the shared array would also be deleted: The *core dump*
  happens because =delete [] data;= is executed twice on the same
  memory, which leads to undefined memory.

- A Rules of Three applies: If your ~class~ manages resources, you must
  define, to adoiv issues like double ~delete~:
  1. A *destructor* to free allocated objects.
  2. A *copy constructor*, which allocates itw own new member storage
     and copies the content of member variables.
  3. A *copy assignment operator*, which deallocates old storage,
     allocates new storage, and copies all member variables.

- The first code fix in [[Vector2]] below includes a copy constructor and
  a copy assignment operator that overloads the assignment
  operator. We also added a separate default constructor =Vect()= which
  in turns calls upon =Vect(int n)=.

        data[i]=a.data[i];
      }
    }

    Vect& Vect::operator=(const Vect& a) {
      if (this != &a) { // no self-assignment
        delete [] data; // delete this->data
        size = a.size;
        data = new int[size];
        for (int i=0;i<size;i++) data[i]=a.data[i];
      }
      return *this;
    }

    Vect::~Vect() { // destructor
      delete [] data;
    }
  #+end_src

- You need =string::npos= because ~npos~ is a member of the ~string~ ~class~,
  not a ~namespace~ member. Otherwise it would not be defined in this
  *scope*.

- ~string::npos~ is defined as =static const size_type npos = -1;= where

  largest possible value, or =std::numeric_limits<size_t>::max()=. If
  the string is not found, the index search function =s.find= returns an
  *impossible* index. ~npos~ is used as a *sentinel value*, a marker that no
  valid index would ever match. This logic is a little twisted, it's
  quite C-style.

* C++ Program and File Organization

- A typical C++ program consists of many files. For example, each
  major ~class~ is placed in its own file.

- There are two common file types:

  1. *Source files* (.cc, .cpp) contain executable statements and data

  ~extern~ indicates that a global variable is defined in another file.

* Writing a C++ Program

- Writing a program in C++ is no different from writing any other
  program. It involves:

  1. Design
  2. Coding
  3. Testing and Debugging.

** Design

- What you need to do:
  1. Decide which classes to use.
  2. Decide how classes should interact.
  3. Decide what data each class will store.
  4. Decide which actions each class will perform.

- Classes have:

  1) *Responsibilities:* The work is done by different *actors*. Each
     actor has a different job. Describe this job using action
     verbs. These actors form the classes for the program.

     Example 1: The only actor for credit card transactions is
     =CreditCard=. It handles all relevant actions. External entities
     like users, banks, or ATMs are abstracted away - their effects
     are modeled through method calls on the =CreditCard= class.

     Example 2: What could the actors be for a library system?
     #+begin_quote
     - =Book= stores =title=, =author=, =status= (checked out/available) data.
     - =Library= manages =Book= collections, can =addBook=, =findBook=, and
       =listAvailableBooks=.
     #+end_quote

  2) *Independence*: The work for each class should be independent from
     the work of other classes. In this way, each class has some
     autonomy over some aspect of the program. Its data are required
     to perform these actions.

  3) *Behaviors:* The consequences of each action are well understood by
     other classes with which it interacts. The set of behaviors is
     also called its *protocol*.

  4) So is this the only way to model for example credit card
  transactions?
  #+begin_quote
  No. Separating the transaction into different actors improves
  clarity, supports data logging, validation, and extensions
  (e.g. fraud detection, transaction history etc.). Example:
  + =CreditCard= stores card info and balance, handles =charge= and =pay=.
  + =Transaction= is a single action, handles =execute= and =getAmount=.
  + =AccountHolder= is the user, can =initiateCharge=, =makePayment=.
  + =Bank= can =authorize= charges, and =process= payments.
  #+end_quote

- With greater experience comes greater skill in recognizing
  patterns. This means when to apply inheritance vs. composition, when
  to extract interfaces, and encapsulate responsibilities. The key to
  OOP is collaboration among objects to reflect real-world
  relationships and produce reusable, maintainable, working code.

** Pseudo-Code

- Pseudo-code is a mixture of natural language and high-level
  programming constructs that describe the main idea behind an
  algorithm.

- The constructs commonly used are:

  1. *Expressions*, especially ~<-~ for ~=~ for the equality relation ~==~.

  2. *Function declarations*: ALGORITHM name(arguments)

  3. *Decisions:* IF [condition] THEN [T-action] ELSE [F-action]

  4. *While-loops*: WHILE [condition] DO [action]

  5. *Repeat-loops*: REPEAT [action] UNTIL [condition]

  6. *For-loops*: FOR [variable-increment-definition] DO [action]

  7. *Array indexing:* A[i] is the i-th cell of A[0] to A[n-1] cells

  8. *Member function calls*: object.method(args)

  9. *Function returns:* RETURN [value]

  10. *Comments:* { [comment] }

- Focus on human readability and understanding over syntax accuracy.

- Each card represents a component of the problem, which will become a
  ~class~ in the program. LHS: write down the responsibilities for the
  component, which may become member functions. RHS: other classes to
  interact with to perform.

- The design process iterates through an action/actor cycle: We first
  identify an action (responsibility) like "make appointment" for the
  class "Patient", and then we determine a suitable actor (component)
  to perform the action, like "Appointment" as a class with its own
  member data (calendar) and member functions ("show appointment").

- On the back of the card, we write down attributes (member data) of
  the class, and relationships, in particular super-classes ("A
  patient is a-kind-of Person"), and aggregations ("A Patient
  has-parts of a Medical History").

** Readability and Style

Main principles:

1. Use meaningful names for identifiers.

2. Capitalize the first letter of each word in an identifier (except
   variables or methods): =VectorSum=, =DeviceManager= for classes,
   =insertItem=, =studentName= for member functions/data,

3. Use named constants and enumerations instead of embedded
   values. These can then be used in more than one class. Fully
   capitalize such constants:
   #+begin_example C++
   const int MIN_CREDITS = 12;
   const int MAX_CREDITS = 24;

   enum YEAR { FRESHMAN, SOPHOMORE, JUNIOR, SENIOR ];
   #+end_example

4. Indent statement blocks.

5. Organize classes in a consistent order:
   1) Public types and nested classes
   2) Public member functions
   3) Protected member functions (internal utilities)
   4) Private member data.

6. Use comments that add meaning:
   1) Inline-comments for quick explanations
   2) Block comments for explanation of a purpose
   3) External comments for more details.

** Testing

- Every programming project must have a testing plan.

- Programs are executed over a representative subset of inputs.

- Every method in the program is tested at least once.

- Every statement in the program is executed at least once.

- Special cases for the input need to be identified and tested.

  Example: When testing a method that sorts an array of integers,
  consider
  1) The array has zero length
  2) The array has one element only
  3) All array elements are identical
  4) The array is already sorted
  5) The array is reverse sorted

- Special conditions for the data structures must be identified and
  tested.

  Example: When using an array to store data, consider
  1) inserting elements at the beginning of the subarray with data
  2) removing elements at the beginning of the subarray with data
  3) inserting elements at the end of the subarray with data
  4) removing elements at the end of the subarray with data.

- If there is a caller-callee relationship (function A calls B),
  functions can be tested in two main ways: top-down or botton-up.

  1) *Bottom-up*: from lover-level functions to higher-level
     functions. Ensures that errors in a method are not caused by
     lower-level functions nested within it.

  2) *Top-down*: from the top to the bottom of the method
     hierarchy. Often includes *stubbing* - replacing a lower-level
     function with a stub that simulates the output of the original
     method. For example if A calls B to get the first line of a file,
     when we test A, B can be replace with a stub that returns a fixed
     string.

** Debugging

- Simple: Insert *print statements* to track values during execution.
- Problem: Remove statements before going to "production".
- Better: Using a debugger with *breakpoints* and *conditional
  breakpoints*.
