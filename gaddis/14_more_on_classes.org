* SOMEDAY Instance and static members

Each instance of a ~class~ has its own copies of the ~class~ instance
variables. If a member variable is declared ~static~, however, all
instances of that ~class~ have access to that variable. If a member
function is declared ~static~, it may be called without any instances of
the ~class~ being defined.

* SOMEDAY Friends of classes

A ~friend~ is a function or ~class~ that is not a member of a ~class~, but
has access to the private members of the ~class~.

* Memberwise assignment

  - [[https://en.cppreference.com/w/cpp/language/operator_assignment.html][See cppreference documentation on assignment operators.]]

  - The assignment operator ~=~ can be used to assign the data of one
    object to another object, or to initialize one object with another
    object's data.

  - By default, each member of one object is copied to its counterpart
    in the other object.

  - We use the =Rectangle= class with interface in =Rectangle.h= and
    implementation in =Rectangle.cpp= ([[RECTANGLE_CPP][code below]]).

* Copy Constructors

- A *copy constructor* is a special constructor that is called whenever
  a new object is created and initialized with another object's data.

- Why have copy constructors at all since we have memberwise
  assignment?
  #+begin_quote
  The default memberwise assignment just copies pointer addresses but
  not the values they're pointing to - then both pointers point to the
  same memory, and deleting one invalidates the other.

  Some data structures maintain internal links (like ~head~ or ~tail~ for
  linked lists), which are easily broken by memberwise copy.

  Data structures may hold file handles or sockets that must be
  uniquely managed: Membership copy does not take this into account.
  #+end_quote

- When duplication (aka *deep copy*) isn't needed, you can use *move
  constructors* instead. Their *shallow copy* avoids unnecessary deep
  copies when handling large data structures and uses temporaries.

* The problem with memberwise copy

- The ~class~ =StudentTestScores= holds the student's name, number of test
  scores, and a pointer to an array of test scores (created with a
  ~private~ member function).

- Code for =StudentTestScores.h= (all member functions defined inline):
  #+name: STUDENTTESTSCORE_H
  #+begin_src C++ :noeval :flags -I ../src/ :tangle ../src/StudentTestScores.h :main no :includes :results none
    #ifndef STUDENTTESTSCORES_H
    #define STUDENTTESTSCORES_H
    #include <string>
    using namespace std;

    const double DEFAULT_SCORE = 0.0;

    class StudentTestScores
    {
    private:
      string studentName;   // student's name
      double *testScores;   // points to array of test scores
      int numTestScores;    // number of test scores

      void createTestScoresArray(int size) // initialize array
      {
        numTestScores = size;
        testScores = new double[size]; // allocate memory
        for (int i=0; i<size; i++)
          testScores[i] = DEFAULT_SCORE;
      }
    public:
      StudentTestScores(string name, int numScores)
      {studentName = name;
        createTestScoresArray(numScores);}
      ~StudentTestScores()
      {delete [] testScores;}
      void setTestScore(double score, int index)
      {testScores[index]=score;}
      string getStudentName() const
      {return studentName;}
      int getNumTestScores() const
      {return numTestScores;}
      double getTestScore(int index) const
      {return testScores[index];}
    };
    #endif
  #+end_src

- The compilation is aborted with the error message:
  #+begin_example
  free(): double free detected in tcache 2
  #+end_example

- What's going on?
  #+begin_quote
  In the copying statement, the constructor of =student2= is never
  called - there's no memory made available for =student2.testScores=.
  Instead, it gets a copy of =student1.testScore= so that both pointers
  point to the same address.
  #+end_quote
  #+attr_html: :width 400px :float nil:
  [[../img/testScores2.png]]

- What's the problem?
  #+begin_quote
  The error message says as much: When one object is destroyed (using
  the C function =free= which is behind =delete=), the pointer of the
  other object would still reference this section of the memory
  although it should no longer be used.
  #+end_quote

- What's the solution?
  #+begin_quote
  The solution to copying dynamically allocate data structures is to
  use a copy constructor that references its own dynamically allocated
  memory, avoiding inadvertent data corruption.

  The copy constructor looks like any other constructor except that it
  has a *reference parameter* of the same class type as the constructor.
  #+end_quote

- Code example: Here, the copy constructor is not really
  necessary. The program copies and alters the member data.

* Operator Overloading 

  - [[https://en.cppreference.com/w/cpp/language/operators.html][See cppreference documentation.]]

  - To "overload an operator" means defining what the operator does when
    it works with user-defined objects.

  - You've already seen (at least) one example:
    #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
      string one = "Hello,";
      string two = " World!\n";

      cout << one + two; // overloaded + operator
      cout << 1 + 2;
    #+end_src

    #+RESULTS:
    : Hello, World!
    : 3

  - Another common example is the division operator ~/~, which works for
    integer and floating-point. Depending on the operands, the
    compiler decides for one of the two ovarloaded division operators.
  
  - Writing custom operators is more intuitive to use. For example,
    compare adding 5 days to a =today= object of a =Date= class:

    #+begin_example C++
      today.add(5);     // adding with a member function `add`
      today += 5;       // adding with an overloaded += operator
    #+end_example

* Example: Adding =Inventory= with overloaded =operator+=

Source: VideoNote 14.1 (p 868)

- Example: an =Inventory= class. In the ~main~ program, we create two
  stores, both =Inventory= objects. 

- If at some point in the future we want to create a store object with
  the combined units of both stores.

- This is how that would have to work now:
  #+name: Inventory1
  #+begin_src C++ :main no :includes :results none
    #include <iostream>
    using namespace std;

    class Inventory
    {
    private:
      int units;
    public:
      Inventory() {units=0;}
      Inventory(int u) {units=u;}
      int getUnits() const {return units;}
    };


    int main()
    {
      Inventory store1(200);
      Inventory store2(100);

      int sum = store1.getUnits() + store2.getUnits();
      Inventory total(sum);
      return 0;
    }
  #+end_src

- It would be more elegant, readable, and conceptually object-oriented
  if we could create an object and assign the sum to it like this:
  #+begin_example C++
  Inventory total;
  total = store1 + store2;
  #+end_example

- The ~+~ is not written to perform this operation. We can do that by
  adding an =operator+= member function overloading the ~+~ operator:
  #+begin_example C++
  Inventory operator+(const Inventory & right)
  {
    int totalUnits = units + right.units;
    Inventory temp(totalUnits);
    return temp;
  }    
  #+end_example

  1) =operator+= tells the compiler to overload the ~+~ operator

  2) The ~return~ type is the type resulting from the operation (an
     =Inventory=).

  3) When you overload a binary operator, the right hand side operand
     is loaded (for example =store2= in the expression =store1 + store2=).

  4) The parameter =right= is passed by reference rather than by value,
     which is more efficient (no copying).

  5) The parameter is a =const Inventory=, which is safe because it
     cannot change the argument.

  6) The =totalUnits= variable performs the operation directly on the
     ~private~ member data.

  7) The statement =total = store1 + store2= is equivalent to:
     #+begin_example C++
     total = store1.operator+(store2);
     #+end_example

- Let's test this with another version of the program:
  #+name: Inventory2
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    using namespace std;

    class Inventory
    {
    private:
      int units;
    public:
      Inventory() {units=0;}
      Inventory(int u) {units=u;}
      int getUnits() const {return units;}
      Inventory operator+(const Inventory & right)
      {
        int total = units + right.units;
        Inventory temp(total);
        return temp;
      }
    };


    int main()
    {
      Inventory store1(200);
      Inventory store2(100);
      Inventory total;

      // Get the sum of the units on hand.
      total = store1 + store2;
      
      // Display the data.
      cout << "Store #1: " << store1.getUnits() << endl
           << "Store #2: " << store2.getUnits() << endl
           << "Total inventory: " << total.getUnits() << endl;                
      return 0;
    }
  #+end_src

* The ~this~ pointer

- The ~this~ pointer is a built-in pointer that every class has. It is
  passed as a hidden argument to all non-~static~ member functions. It
  always points to the instance of the class making the function call.

- Example: =StudentTestScores=.
  #+begin_example C++
  cout << student1.getStudentName(); // `this` points to `student1`
  cout << student2.getStudentName(); // `this` points to `student2`  
  #+end_example

- There are three main cases when ~this~ is needed:

  1) Disambiguation (name shadowing): when a parameter or local
     variable has the same name as a data member.

  2) Getting the object's address: =cout << this;=

  3) Returning the current object when overloading operators or
     chaining methods: =obj.setID(10).setScore(95).setLevel(3);=
  
* PRACTICE The ~this~ pointer (disambiguation and object address)

- Here is a simple =Student= class interface with inline implementation,
  a constructor that uses ~this~ to clarify that we mean the member

* PRACTICE The ~this~ pointer (method chaining)

- In this implementation of =Student=, a student has ID and score
  attributes. By returning the value that ~this~ points at (dereferenced
  ~*this~), the member functions can be chained:

  #+name: this demo 2
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    #include <string>
    using namespace std;

    class Student // class
    {
    private:
      int id;
      int score;
    public:
      Student(int i, int s) // constructor
        : id(i), score(s) {}

      // Each setter/mutator function returns *this so it can be chained
      Student & setID(int i)
      {
        id = i;
        return *this;
      }
      Student & setScore(int s)
      {
        score = s;
        return *this;
      }
      void printInfo() // print data member info
      {
        cout << "ID "       << id
    	 << ", Score: " << score << endl;
      }
    };

    int main() // test class
    {
      Student s(1, 0); // Student s has id=1 and score=0
      s.printInfo();
      
      s.setID(100).setScore(95); // chained member function calls
      s.printInfo();
            
      return 0;
    }
  #+end_src

  #+RESULTS: this demo 2
  : ID 1, Score: 0
  : ID 100, Score: 95

- Why is the ~return~ type of the setter functions =Student & setID= and
  not just =Student setID=?
  #+begin_quote
  Beause ~this~ is a *pointer* (=Student *=) but ~*this~ is a reference to the
  object itself (=Student &=). So the setter function's ~return~ type must
  be a *reference*, too.
  #+end_quote

- What would happen if you would use the ~return type~ =Student setID=
  instead? Try it!
  #+begin_quote
  It would still work but the compiler would make a *copy* of the object
  each time you ~return~. Chaining would still work but every step in
  the chain would operate on a temporary copy - changes would be lost
  after the temporary is destroyed!
  #+end_quote

* Assignment operator overloading (=operator==) - copy assignment

- Copy constructors solve the initialization problem with objects
  containing pointer members but they do not work with assignment:
  They are invoked only when an object is created.

- If =student2= and =student1= already exist, then =student2 = student1=
  uses memberwise assignment. To change this, ~=~ must be overloaded as
  =operator==.

- For the [[STUDENTTESTSCORE2_H][StudentTestScores]] ~class~ (version 2 with copy constructor),
  this code overloades the assignment operator: Recall that this class
  defines a student's =name= and a dynamically allocated array
  =testScores= of length =numTestScores=.

  #+begin_example C++
  const StudentTestScores operator=(const StudentTestScores &right)
  {
    if (this != & right)
    {
      delete [] testScores;
      studentName   = right.studentName;
      numTestScores = right.numTestScores;
      for (int i = 0; i < numTestScores; i++)
         testScores[i] = right.testScores[i];
    }
  }
  #+end_example

- Explanation of the function header:
  #+attr_html: :width 600px :float nil:
  #+caption: Function header for StudentTestScores::operator=
  [[../img/operator.png]]

  1) Function returns a =const StudentTestScores= object that cannot be
     modified.

  2) The name is =operator== which specifies that the ~=~ operator is
     being overloaded and will be called whenever the object on the
     *left* side of the assignment is a =StudentTestScores= object.

  3) The parameter =const StudentTestScores & right= references the
     object on the *right* hand side of the assignment operator.

- The following two statements do the same thing for two
  =StudentTestScores= objects =student1= and =student2=:
  #+begin_example C++
  student2 = student1;
  student2.operator=(student1);
  #+end_example

- Explanation of the condition =if (this !== =&right)=: 
  #+attr_html: :width 250px :float nil:
  [[../img/operator2.png]]

  The condition is true if the object on the left side of ~=~ (which
  ~this~ points at) is the same as the object on the right side - this
  is self-assignment.
  
- Explanation of the ~return~ value, =return *this=: The expression =*this=
  dereferences the =this= pointer and gives us the object whose ~const~
  copy is returned. This is to enable *chaining* assignments as in:
  a = b = c = d.

- This statement works like this:
  1) c=d assigns d to c, then returns the new value of c
  2) b=c assigns the new value of c to b, then returns the new b
  3) a=b assigns the new value of b to a, then returns the new a.

   #+begin_quote
   The compiler-generated assignment operator assigns each
   (non-static) data member of the left object the corresponding
   member of the right objects - shallow per-member ~operator=~ copy.
   #+end_quote

7. Describe two instances when memberwise assignment occurs.
   #+begin_quote
   - Assigning one existing object to another: a = b (if there's no
     user-defined =operator==). 
   - Assigning the result of a function (returned by value) to an
     existing object (if there's no user-defined =operator==).
   #+end_quote

8. When should memberwise assignment not be used?
   #+begin_quote
   When the class manages resources needeing deep/controlled copy,
   e.g. pointers. You must write a copy constructor (or overload the
   ~operator=~).
   #+end_quote

9. When is a copy constructor called?
   #+begin_quote
   - On initialization from an existing object.
   - When passing/returning by value (to copy the parameter/result).
   #+end_quote

10. How does the compiler know that a constructor is a copy
    constructor?
    #+begin_quote
    The constructor's parameter is a reference to the class.
    #+end_quote
