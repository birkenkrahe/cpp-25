* Overview

- What is a ~vector~?
  #+begin_quote
  A ~vector~ is a sequential container of elements of the same data
  type: Integers, doubles, characters, strings, classes, etc.
  #+end_quote

- Why use ~vector~ instead of arrays?
  #+begin_quote
  1. You don't have to declare the size of a ~vector~ when you define
     it.
  2. You can add elements to, or delete from it at runtime, and the
     ~vector~ automatically adjusts its size.
  3. A ~vector~ can report the number of elements it contains.
  #+end_quote

- What do you have to do to use ~vector~?
  #+begin_quote
  To use ~vector~ you have to ~#include <vector>~ and if you want to avoid
  having to write ~std::vector~, you need to add: ~using namespace std;~
  #+end_quote

* Vector constructors

- *Tip:* Check ~std::vector~ [[https://en.cppreference.com/w/cpp/container/vector.html][at cppreference.com]] before and after this
  section to see if your understanding changed!

- ~vector~ has five constructors, that is five different ways of
  creating containers. We illustrate these with working code.

  1. *Default constructor:* creates an empty ~vector~
     #+begin_src C++ :main yes :includes <iostream> <vector> :namespaces std :results none :exports both :noweb yes
       vector<string> numbers; // an empty vector of integers
     #+end_src

  2. *Fill constructor:* creates a ~vector~ of length ~size~
     #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
       vector<bool> values (3, 0); // a vector of three booleans (false)
       for (auto elem : values) cout << boolalpha << elem << " ";
     #+end_src

     #+RESULTS:
     : 1 100 200 300 2 3

  3. *Range constructor:* creates a ~vector~ of a range of values
     specified by two iterators.
     #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
       vector<int> vec {1,2,3,4,5,6,7,8};
       auto it1 = vec.begin() + 2; // 3
       auto it2 = vec.end() - 2;   // 7
       cout << *it1 << " " << *it2 << endl;

       vector<int> vec2(it1,it2);  // sub-range from it1 (3) to it2 (7)
       for (auto elem : vec2) cout << elem << " ";
     #+end_src

     #+RESULTS:
     : 3 7
     : 3 4 5 6

  4. *Copy constructor*: creates a ~vector~ by copying another ~vector~
     #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
       vector<string> names = {"Jimmy", "Johnny", "Jenny"};
       vector<string> names2(names);  // copy of names vector
       for (auto elem : names2) cout << elem << " ";
     #+end_src

     #+RESULTS:
     : Jimmy Johnny Jenny

* List of ~vector~ member functions

There are 40 (!) member functions in C++20 (including the constructors
and overloaded operators). We order member functions by category:

1. Construction and assignment
2. Element access
3. Iterator support
4. Capacity operations
5. Modifiers
6. Allocator
7. Comparisons

This *function overload* is intential: STL containers are designed for
performance, generality, and type safety, favoring completeness over
simplicity. C takes the opposite view: Simple over safe and complete.

1. *Construction & Assignment*

   | Function                    | Description                                 |
   |-----------------------------+---------------------------------------------|
   | constructor                 | Creates vector                              |
   |                             | (default, copy, move, range, init)          |
   | operator=                   | Assigns contents                            |
   | assign(size, value)         | Replaces contents from range or count+value |
   | assign(iterator1, iterator2 |                                             |

2. *Element Access*

   | Function   | Description                                          |
   |------------+------------------------------------------------------|
   | at(index)  | Returns reference to element with bounds checking    |
   | operator[] | Returns reference to element without bounds checking |
   | front()    | Returns reference to first element                   |
   | back()     | Returns reference to last element                    |
   | data()     | Returns pointer to first element in container        |

3. *Iterators*[fn:1]

   | Function  | Description                         |
   |-----------+-------------------------------------|
   | begin()   | Iterator to first element           |
   | end()     | Iterator past last element          |
   | cbegin()  | Const iterator to first element     |
   | cend()    | Const iterator past last element    |
   | rbegin()  | Reverse iterator to last element    |
   | rend()    | Reverse iterator before first       |
   | crbegin() | Const reverse iterator to last      |
   | crend()   | Const reverse iterator before first |

4. *Capacity*

   | Function         | Description                                      |
   |------------------+--------------------------------------------------|
   | empty()          | Returns true if container is empty               |
   | size()           | Returns number of elements                       |
   | max_size()       | Max number of elements (theoretically) possible  |
   | capacity()       | Returns number of elements that underlying array |
   |                  | can hold, without reallocating the array[fn:2]   |
   | resize(n)        | Changes number of elements to n                  |
   | resize(n, value) | Changes number of elements to n - if size() < n  |
   |                  | then the new elements are initialized with value |
   | reserve(n)       | Increases capacity to n (preallocation)          |
   | shrink_to_fit()  | Requests to reduce capacity() to be equal size() |

5. *Modifiers*

   | Function             | Description                                |
   |----------------------+--------------------------------------------|
   | clear()              | Erases all elements                        |
   | insert(it, n, value) | Inserts n new elements at position it      |
   |                      | with that (single) value                   |
   | emplace(it, value)   | Constructs element in-place at position it |
   |                      | (new element inserted before position it)  |
   | erase(it)            | Removes element at position it and returns |
   |                      | iterator pointing to the next element      |
   | push_back(value)     | Adds element to end                        |
   | emplace_back(value)  | Constructs element at end                  |
   | pop_back()           | Removes last element                       |
   | swap(second)         | Swaps content of calling vector and of the |
   |                      | second object (same data type)             |

6. *Allocator*

   | Function        | Description                                  |
   |-----------------+----------------------------------------------|
   | get_allocator() | Returns allocator (custom memory management) |

7. *Comparisons* (C++20)

   | Function    | Description                                     |
   |-------------+-------------------------------------------------|
   | operator==  | Equality comparison                             |
   | operator<=> | Three-way comparison (spaceship operator)[fn:3] |

* Minimal ~vector~ API for Data Structures

Fortunately, you don't need to memorize 40 functions - only these 10
are really critical for competently using ~vector~ containers:

|    | Category     | Function       | Purpose              |
|----+--------------+----------------+----------------------|
|  1 | Access       | operator[]     | Random access        |
|  2 | Capacity     | size()         | Track current size   |
|  3 | Capacity     | reserve()      | Preallocate storage  |
|  4 | Capacity     | capacity()     | Know current storage |
|  5 | Modification | push_back()    | Add element to end   |
|  6 | Modification | pop_back()     | Remove last element  |
|  7 | Modification | insert()       | Insert at position   |
|  8 | Modification | erase()        | Remove at position   |
|  9 | Modification | clear()        | Remove all elements  |
| 10 | Iteration    | begin(), end() | Traverse elements    |

* Using an iterator with ~vector~

- The ~vector~ class supports the use of these iterators:
  1) ~iterator~ (forward iterator)
  2) ~const_iterator~ (constant iterator)
  3) ~reverse_iterator~ (backward iterator)
  4) ~const_reverse_iterator~ (constant backward iterator)

- Compare the member support functions for getting iterators: ~begin()~,
  ~end()~, ~cbegin()~, ~cend()~, ~rbegin()~, ~rend()~, ~crbegin()~, ~crend()~.

- You can simplify the definition of an iterator with ~auto~. In the
  following code block loop 1 and loop 2 are equivalent:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    vector<int> num;

    // loop 1
    vector<int>::iterator it;
    for (it = num.begin(); it != num.end(); it++)

      // loop 2
      for (auto it = num.begin(); it != num.end(); it++)
  #+end_src

  #+RESULTS:

- Where does =it= point? How many times does the loop run?
  #+begin_quote
  Since =num= is empty, =num.begin()= equals =num.end()= and the loop never
  runs. =it= does not point to any valid element. No memory is reserved
  for =num= until elements are inserted or ~reserve(n)~ is called.
  #+end_quote

* Inserting new elements into a ~vector~

- To insert one ore more new elements at a specified position in a
  ~vector~, use ~insert~. The full definition is complicated (see
  [[https://en.cppreference.com/w/cpp/container/vector/insert][cppreference.com]])!

- There are multiple overloads (alternative uses) but these three are
  most common:

  1. Insert a single =value= of type =T= at the specified position:
     #+begin_example C++
     iterator insert(iterator pos, const T& value);
     #+end_example

  2. Insert =count= copies of a =value=:
     #+begin_example C++
     iterator insert(iterator pos, size_type count, const T& value);
     #+end_example

  3. Insert a range of values:
     #+begin_example C++
     iterator insert(iterator pos, iterator pos1, iterator pos2);
     #+end_example

- The ~iterator~ is like a bookmark inside the vector. Insertion happens
  before the iterator position.

- Example: inserting a single value
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    vector<int> v{1,2,3,4,5};
    for (auto element : v) cout << element << " "; cout << endl;
    auto it = v.begin() + 2; // points to element 4
    v.insert(it, 3);         // insert 3 before 4
    for (auto element : v) cout << element << " ";
  #+end_src

  #+RESULTS:
  : 1 2 3 4 5
  : 1 2 3 3 4 5

- The function returns an iterator to the newly inserted element:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    vector<int> v {1,2,3,4,5};
    auto inserted = v.insert(v.begin(), 99);
    cout << *inserted << endl;
  #+end_src

  #+RESULTS:
  : 99

- Example: Insert multiple copies
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    vector<int> v {1,2,5};
    v.insert(v.begin() + 2, 2, 3); // insert two 3s before 5
    for (auto element : v) cout << element << " ";
  #+end_src

  #+RESULTS:
  : 1 2 3 3 5

- Example: Insert a range of values:
  #+begin_src C++ :main yes :includes <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    vector<int> a{10,20};
    vector<int> b{1,2,3};
    a.insert(a.begin() + 1, b.begin(), b.end()); // insert b before 20
    for (auto element : a) cout << element << " ";
  #+end_src

  #+RESULTS:
  : 10 1 2 3 20

- Does ~insert~ modify a vector in-place or does it create a copy?
  #+begin_quote
  - The vector is modified in-place (you're not getting a new copy)
    but memory management does take place.
  - If the vector does not have enough capacity, a new, larger array
    is allocated, all elements are moved to the new memory, the old
    array is deleted, and all iterators, pointers, references become
    invalid.
  #+end_quote

* Storing ~class~ objects in a ~vector~

- Remember that a ~class~ is a user-defined data structure. It can be
  used like a type when defining a ~vector~.

- The file =Product.h= contains the definition of the =Product=
  ~class~. Below, we will define and initialize a ~vector~ to hold =Product=
  objects.

- =Product.h=: Products have a ~private~ =name= and =units=. You can set both
  of these with =setName= and =setUnits=, and you can get their values
  with =getName= and =getUnits=.

  #+name: PRODUCT_H
  #+begin_src C++ :tangle ../src/Product.h :main no :includes :results output :exports both
    #ifndef PRODUCT_H
    #define PRODUCT_H
    #include <string>
    using namespace std;

    class Product
    {
    private:
      string name;
      int units;
    public:
      Product(string n, int u) { name = n; units = u;}
      void setName(string n) { name = n; }
      void setUnits(int u) { units = u; }
      string getName() const { return name; }
      int getUnits() const { return units; }
    };
    #endif
  #+end_src

- Next, we ~#include~ the =Product.h= file in the ~main~ program, create a
  few =Product= objects, store them in a ~vector~, and print their
  data. The file is called =Products.cpp=.

  #+name: PRODUCT_CPP
  #+begin_src C++ :tangle Products.cpp :flags -I ../src :main no :includes :results output :exports both
    #include <iostream>
    #include <vector>
    #include "Product.h"
    using namespace std;

    int main()
    {
      // Create a vector of Product objects.
      vector<Product> products =
        {
          Product("T-Shirt", 20),
          Product("Calendar", 25),
          Product("Coffee Mug", 30)
        };

      // Display the vector elements.
      for (auto product : products)
        {
          cout << "Product: " << product.getName()   << endl
               << "Units:   " << product.getUnits() << endl;
        }
      return 0;
    }
  #+end_src

* Displaying vectors with ~class~ objects using an iterator

- Let's create a simple ~Student~ class, create a couple of students
  with a =name= and an =id=, add them to a ~vector~ of =Student= objects named
  =roster= and display the contents of that vector using an iterator on
  =getName()= and =getID()= functions.

- The main thing to remember is that the iterator works like a pointer
  to the container. So to use a member function like =getName()= on the
  container, we would call =roster.getName()= but to call it on the
  iterator =it= that points at =roster=, we would call: =it->getName()=.

  #+begin_src C++ :main no :includes :results output :exports both

    #include <string>
    #include <vector>
    using namespace std;

    class Student {
    private:
      string name;
      int id;
    public:
      Student(const string& n, const int i) : name(n), id(i) {}
      string getName() { return name; }
      int getID() { return id; }
    };

    int main()
    {
      // Create a vector of Student objects.
      vector<Student> roster = {
        Student("Alice", 1001),
        Student("Bob",1002)
      };

      // Use an iterator to display the vector contents.
      for (auto it  = roster.begin(); it != roster.end(); it++)
        {
          cout << "Student name = " << it->getName() << endl  // (*it).getName
               << "Student ID =   " << it->getID()   << endl; // (*it).getID
        }

    }

  be inefficient. With C++, two new functions, ~emplace~ and

- Is there any advantage from using the range-based ~for~ loop vs. the
  iterator-controlled ~for~ loop?
  #+begin_quote
  - Use the simple range-based loop when you want to read or modify
    each element directly and you don't need the index or change the
    container structure (e.g. erase elements).
  - Use the iterator-controlled loop when you need fine control over
    iteration (by index) and when you want to change container
    structure.
  #+end_quote

- Does it matter if you use ~auto~, ~auto&~ or ~const auto&~ in a container
  loop?
  #+begin_quote
  | Syntax      | Meaning                       | When to Use          |
  |-------------+-------------------------------+----------------------|
  | ~auto~        | Copy each element             | Copying is cheap     |
  | ~auto&~       | Non-const ref to each element | Need to modify       |
  | ~const auto&~ | Const ref to each element     | Don't need to modify |
  #+end_quote

  location in the ~vector~. Its first argument is an iterator, and the
  new element will be constructed at the position right before the
  iterator. After the iterator, you pass the list of arguments to be
  forwarded to the new object's constructor.

* Storage allocation functions for ~vector~

- The ~vector~ is a wrapper for a C-style array. When its array is full,
  and another element is added, the ~vector~ needs to
  1) allocate a new array with more memory
  2) copy all elements of the old array to the new array
  3) deallocate the old array.

- This wouldn't be very efficient if if had to be done every time a
  new element is added. Therefore, the ~vector~ object has more memory
  than it needs.

- A ~vector~ object has five important functions related to size:
  1. The number of elements that are stored in the ~vector~: ~size()~
  2. The number of elements that can be stored in the ~vector~ without
     having to reallocate the underlying array, ~capacity()~
  3. The number of elements that the ~vector~ can ever store, ~max_size()~
  4. The ~reserve~ member function to increase the vector's capacity
  5. The ~shrink_to_fit()~ function to decrease the vector's capacity so
     that it is the same as ~size()~.

6. If your program will add a lot of objects to a ~vector~, is it best
   to use the ~insert~ member function, or the ~emplace~ member function,
   and why?

   #+begin_quote
   Using the ~insert~ (and the ~push_back~) member function may create
   copies of objects when inserting them into the ~vector~, especially
   if you pass in fully constructed objects. In contrast, ~emplace~ (and
   emplace_back) constructs the object in-place, directly in the
   vector's memory, avoiding unnecessary copying or moving.

   This is typically more efficient, especially when dealing with
   complex objects. Therefore, ~emplace~ is preferred when adding many
   objects, particularly if they can be constructed directly with
   constructor arguments.
   #+end_quote

7. Internally, how does a ~vector~ store its elements?
   #+begin_quote
   A ~vector~ stores its elements in a contiguous block of memory on the
   heap (the "free store") just like a dynamically allocated C-style
   array. It manages memory automatically and resizes as needed by
   allocating a larger array and copying existing elements when
   ~capacity~ is exceeded.
   #+end_quote

8. The ~vector~ class has a ~size~ and a ~capacity~ member function. What is
   the difference between these two member functions?
   #+begin_quote
   The ~size~ function returns the current size of the ~vector~ (in number
   of elements) while the ~capacity~ function returns the number of
   elements that can be stored before resizing is needed. It can be
   changed with the ~reserve~ function.
   #+end_quote

* Glossary

| TERM                 | EXPLANATION                                   |
|----------------------+-----------------------------------------------|
| Fill constructor     | ~vector<dataType> name(size, value);~           |
| Range constructor    | ~vector<dataType> name(iterator1, iterator 2);~ |
| Copy constructor     | ~vector<dataType> name(vector2);~               |
| Element access       | Functions like ~at(index)~ or ~operator[]~        |
| Iterator functions   | Support functions like ~begin()~ and ~end()~      |
| Capacity functions   | Size management like ~size()~, ~empty()~          |
| Modifiers            | Like ~push_back(val)~, ~pop_back()~, ~clear(~)      |
| Comparison operators | Like ~operator=~ and ~operator<=>~                |
