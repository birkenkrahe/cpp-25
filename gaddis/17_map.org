- What is a ~map~?
  #+begin_quote
  A ~map~ is an associative container whose elements are key-value
  pairs. To retrieve a value from a map, you use the key that is
  associated with that value - like looking up a word in a dictionary
  where the words are the keys, and the definitions are the
  values. A related concept is the parallel array.
  #+end_quote

- Why use ~map~ objects?
  #+begin_quote
  Maps allow fast key-based lookup. Elements are maintained in sorted
  key order and keys cannot be duplicated. Perfect for symbol tables
  (like variable-type-address, frequency counting (e.g. tracking how
  many times a word occurs in a text), and settings storage
  (e.g. "theme" -> "dark").
  #+end_quote

- How is a ~map~ key different from an index, which is also unique,
  cannot be duplicated, and automatically ordered?
  #+begin_quote
  Maps generalize the idea of an index: the key can be any type
  (~string~, ~class~, etc.) not just integers, and storage does not need
  to be contiguous or pre-sized.
  #+end_quote

- What do you have to do to use ~map~?
  #+begin_quote
  You have to ~#include~ the ~<map>~ header and use the
  ~std::map<Key,Value>~ syntax.
  #+end_quote

* Simple example

- This program generates the map shown in the figure earlier.

  #+name: map demo
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    #include <map>
    #include <string>
    using namespace std;

    int main()
    {
      // Create a map of employee IDs and associated names.
      map<int,string> employees;
      employees[101] = "Jimmy Jones";
      employees[102] = "Albert Smith";
      employees[103] = "Jenny Brown";
      employees[104] = "Johnny Miller";

      // Create a map iterator.
      map<int,string>::iterator iter;

      // Use the iterator to display each map element.
      for (iter = employees.begin(); iter != employees.end(); iter++)
        {
          cout << "ID: "   << iter->first  << ", "
               << "Name: " << iter->second << endl;
        }
      return 0;
    }
  #+end_src

  #+RESULTS: map demo
  : ID: 101, Name: Jimmy Jones
  : ID: 102, Name: Albert Smith
  : ID: 103, Name: Jenny Brown
  : ID: 104, Name: Johnny Miller

- The map key-value pairs can be accessed using the overloaded ~[]~
  operator. A ~for~ loop using an iterator returns a pointer to each
  key-value pair. The key is accessed with ~first~, and the value with
  ~second~.

- You could access key and value also by explicit dereferencing:
  #+begin_example
  iter->first  == (*iter).first
  iter->second == (*iter).second
  #+end_example

* How to get a ~map~

You can get a ~map~ in three ways:

1. With a *default constructor*: as seen in the simple example. This
   creates an empty map.
   #+begin_example
   map<keyDatatype, valueDatatype> name;
   #+end_example

2. With a *range constructor*: Creates a ~map~ object that contains a
   range of values specified by two iterators (bookmarks).
   #+begin_example
   map<keyDatatype, valueDatatype> name(iterator1, iterator2);
   #+end_example

   Example: Using an initializer list to create the map.
   #+begin_src C++ :main yes :includes <iostream> <string> <map> :namespaces std :results output
     map<int, string> fruit {{1,"apple"},{2,"banana"},{3,"cherry"}};
     map<int, string> fruit2(fruit.begin(), fruit.end()); // copy fruit
     for (auto iter=fruit2.rbegin();iter!=fruit2.rend();iter++) // reverse iterator
       cout << iter->first;
   #+end_src

   #+RESULTS:
   #+begin_example
    Canberra is the capital of Australia
    Brasilia is the capital of Brazil
      Ottawa is the capital of Canada
       Paris is the capital of France
      Berlin is the capital of Germany
   New Delhi is the capital of India
        Rome is the capital of Italy
       Tokyo is the capital of Japan
     Nairobi is the capital of Kenya
      Madrid is the capital of Spain
   #+end_example

3. With another ~map~ (copy constructor): the object is a ~map~ that is a
   copy of another ~map~ object. Key and value data types must be the
   same.
   #+begin_example
   map<keyDatatype, valueDatatype> name(map2);
   #+end_example

   Example:
   #+begin_src C++ :main yes :includes <iostream> <string> <map> :namespaces std :results output
     map<int,string> map2 {{1,"jack"},{2,"millie"},{3,"nanny"},{4,"poppy"},{5,"rosie"}};
     map<int,string> map1(map2);
     map<int,string>::iterator it;
     for (auto iter=map1.begin();iter!=map1.end();iter++)
       cout << iter->first << ", " << iter->second << endl;
   #+end_src

* Member functions of ~std::map~

Most of these are the usual suspects that you already know from the
~vector~ class because though associative, a ~map~ is still a *container*.

See [[https://en.cppreference.com/w/cpp/container/map.html][cppreference.com]] for a complete list of member functions.

1. Capacity
   - ~empty()~ :: true if map is empty
   - ~size()~ :: number of key-value pairs

2. Element access
   - ~at(key)~ :: access value at key (throws if key missing)
   - ~operator[]~ :: access or insert value by key

3. Modifiers
   - ~insert(pair)~ :: insert key-value pair in-place
   - ~emplace(pair)~ :: construct & insert element in-place
   - ~erase(key)~ :: erase by key
   - ~clear()~ :: remove all elements
   - ~swap(other_map)~ :: exchange contents with another map

4. Lookup
   - ~find(key)~ :: returns iterator to key or ~end()~
   - ~count(key)~ :: returns 1 if key exists, else 0

5. Iterators
   - ~begin()~, ~end()~ :: forward iteration
   - ~rbegin()~, ~rend()~ :: reverse iteration

6. Range
   - ~lower_bound(key)~ :: first key ≥ given key
   - ~upper_bound(key)~ :: first key > given key
   - ~equal_range(key)~ :: pair of lower/upper bound iterators

* Adding values to a ~map~ with ~insert~

- ~std::pair~ can store two heterogenous objects as a single unit. It's
  a special case of a ~std::tuple~ with two elements, with two member
  variables, ~first~ and ~second~. ~pair~ is declared in ~<utility>~ (which is
  automatically included with ~<map>~).

- When an element is stored in a ~map~, it is stored as a ~pair~ object:
  the element's key is stored in the ~first~, and the value is stored in
  the ~second~ member variable.

- The ~map~ class member function ~insert~ addes a ~pair~ object as an
  element to the map. You can use ~make_pair(key,value)~ to make a pair.

- In the following code, we insert three additional employee data in
  our existing non-empty ~map~ =emp=:

  #+name: map insert demo
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    #include <map>
    using namespace std;

    int main()
    {
      // Create and initialize a map with a list.
      map<int,string> emp = {{101,"Jim Jones"},{105,"Adam Miller"}};

      // Insert new key-value pairs in the map.
      emp.insert(make_pair(102, "Beth Young"));
      emp.insert(make_pair(103, "Jake Brown"));
      emp.insert(make_pair(104, "John Smith"));
      emp.insert(make_pair(105, "Peter Simon")); // duplicate key (ignored)
      emp.insert(make_pair(106, "John Smith")); // duplicate value

      // Iterate over the map and display the key-value pairs.
      for(auto it=emp.begin();it!=emp.end();it++)
        {
          cout << it->first << ", " << it->second << endl;
        }
      return 0;
    }
  #+end_src

  #+RESULTS: map insert demo
  : 101, Jim Jones
  : 102, Beth Young
  : 103, Jake Brown
  : 104, John Smith
  : 105, Adam Miller
  : 106, John Smith

* Finding values in a ~map~ with ~find~ using a key

- To find a value in a ~map~, call the ~find(key)~ member function and

* Retrieving values from a ~map~ with ~at~ using a key

- To retrieve a value from a ~map~, call the ~at(key)~ member function and
  pass the key of the element associated with the desired value. If it
  exists, the value is returned, otherwise an exception is thrown.

- To prevent the exception to be thrown, call the ~count(key)~ function
  that returns only 1 (~true)~ if the argument key exists.

- Code example: Using a ~map~ of employee IDs and names to find an
  employee.

  #+name: retrieve with at
  #+begin_src C++ :main yes :includes <map> <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both :noweb yes
    map<int,string> emp =
      {{101,"Jim Jones"} , {102,"Adam Miller"},
       {103,"Beth Young"}, {104, "Jake Brown"}};

    // Retrieve the employee with ID 103
    if (emp.count(103))
      cout << emp.at(103) << endl;
     else
       cout << "Employee not found.\n";

    // Retrieve the employee with ID 109 (non-existing)
    if (emp.count(109))
      cout << emp.at(109) << endl;
     else
       cout << "Employee not found.\n";
  #+end_src

  #+RESULTS: retrieve with at
  : Beth Young
  : Employee not found.

* Difference between retrieval with ~find~ or ~at~

- Both ~map::find~ and ~map::at~ access elements in a ~map~ by key but they
  differ in purpose, return type, and error behavior:

- Here is a detailed comparison:

  | Feature                | ~map::find(key)~     | ~map::at(key)~        |
  |------------------------+--------------------+---------------------|
  | Return type            | iterator           | reference to value  |
  | Missing key behavior   | Returns ~end()~      | Throws ~out_of_range~ |
  | Key existence check    | Yes                | No (use ~count~)      |
  | Safe if key is missing | Yes                | No                  |
  | Exception-free         | Yes                | No                  |
  | Modifies map?          | No                 | No                  |
  | Usable on ~const map~    | Yes                | Yes                 |
  | Typical use case       | Conditional access | Guaranteed access   |

* Deleting ~map~ elements

- You can delete an element with ~erase(key)~. It returns 1 (~true~) if
  the key exists, or 0 (~false~) otherwise.

- Example:
  #+name: erase map value
  #+begin_src C++ :main no :includes :results output :exports both
    #include <iostream>
    #include <map>
    using namespace std;

    int main()
    {
      // Create and initialize a map with a list.
      map<int,string> emp =
        {{101,"Jim Jones"} , {102,"Adam Miller"},
         {103,"Beth Young"}, {104, "Jake Brown"}};

      // Delete the employee with the ID 103.
      emp.erase(103);

      // Display the content of the map.
      for (map<int,string>::iterator it = emp.begin();
           it != emp.end();
           it++)
        cout << it->first << ", " << it->second << endl;

      return 0;
    }
  #+end_src

* Iterating over a ~map~ with a range-based loop

- If you don't want to mess with individual elements, you can use a
  range-based ~for~ loop to iterate over a map.

- The code below shows three different implementations of this loop:
  1) Using ~auto~ instead of the explicit data type.
  2) Using the ~class~ for a key-value pair, ~pair<keyType, valueType>~.
  3) Using a structured binding declaration ~auto [key,value]~.

  #+begin_src C++ :main yes :includes <map> <iostream> <cstdlib> <string> <fstream> <vector> :namespaces std :results output :exports both
    // Create a map of student IDs and their names
    map<int,string> students =
      { {101, "Jill Johnson"}, {102, "James Henry"},
        {103, "Kayla Jones"}, {104, "Marie Jefferson"} };

    // Display all student names with auto
    for (auto s : students) cout << s.second << " ";
    cout << endl;
    // Display all student names with pair<keyType,valueType>
    for (pair<int,string> s : students) cout << s.second << " ";
    cout << endl;
    // Display all student names with auto[k,v]
    for (auto[k,v] : students) cout << v << " ";
  #+end_src

  #+RESULTS:
  : Jill Johnson James Henry Kayla Jones Marie Jefferson
  : Jill Johnson James Henry Kayla Jones Marie Jefferson
  : Jill Johnson James Henry Kayla Jones Marie Jefferson

- The *structured binding declaration* defines two variables, =k= and
  =v=. Each time the loop iterates, a ~pair~ object from the =students= ~map~
  is retrieved, the ~pair~ object is unpacked with the ~first~ member
  assigned to =k= and the ~second~ member assigned to =v=.

* Using an iterator with a ~map~

* Other ~map~ classes: ~unordered_map~, ~multimap~, ~set~

- The ~unordered_map~ is the basis of the hash table. Its keys are not
  sorted and it has better performance for large maps. Otherwise
  working with it is just like ~map~ except that you include
  ~<unordered_map>~ and use the ~unordered_map~ keyword. This data
  structure is the basis of hash tables (vs. trees).

- The ~multimap~ class allows duplicate (ordered) keys. It uses the
  ~<map>~ directive. For example in a phone book application, you could
  store names and phone numbers as values. If a person has multiple
  phone numbers, you can store multiple elements using their name as
  key.
  #+attr_html: :width 300px :float nil:
  [[../img/multimap.png]]

- A limitation of the ~multimap~ is that the ~[]~ operator is not
  overloaded so that you cannot add elements using it. Use ~emplace~ or
  ~insert~ instead.

- The ~multimap~ class uses the *binary tree* data structure, while the
  ~unordered_multimap~ uses a *hash table*.

* Glossary

| TERM                      | EXPLANATION                                      |
|---------------------------+--------------------------------------------------|
| Map                       | Associative container of key-value pairs         |
| ~iterator->first~           | Access the key element of map element            |
| ~iterator->second~          | Access the value element of a map element        |
| ~map<T,T> name~             | Default constructor for a map                    |
| ~map<T,T> name(other_map)~  | Copy constructor for map                         |
| ~map<T,T> name(it1,it2)~    | Range constructor for map                        |
| ~emplace(key, value)~       | Inserts an element constructed in-place          |
| ~insert(make_pair(k,v))~    | Inserts an existing pair object                  |
| ~at(key)~                   | Accesses value by key; throws if key not found   |
| ~find(key)~                 | Returns iterator to key or ~end()~ if not found    |
| ~count(key)~                | Returns 1 if key exists, 0 otherwise             |
| ~erase(key)~                | Removes element by key; returns 1 if found       |
| ~crbegin(), crend()~        | Return const reverse iterators for map traversal |
| ~auto [k, v]~               | Structured binding for unpacking map pairs       |
| ~[]~ (operator)             | Accesses or inserts (or creates) value by key    |
| Class as map key          | Custom objects can be keys if ~<~ is overloaded    |
| ~operator<~                 | Required to use custom class as map key          |
| ~map<Class, T>~             | Declares a map with class objects as keys        |
| ~initializer list for map~  | Inline using brace-enclosed {key, value} pairs   |
| Range-based loop over map | ~for (auto [k,v] : map)~ unpacks key/value         |
